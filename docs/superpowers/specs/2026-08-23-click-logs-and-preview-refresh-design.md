# 点击链路日志与一键刷新预览设计

## 目标

增加两项排查和发布辅助能力：

1. 在小程序工作台记录“开始新创作”等入口的点击、跳转成功、跳转失败和兜底重开结果。
2. 在项目本地提供一个命令，自动校验工程、打正式包、调用微信开发者工具生成最新预览二维码。

## 方案

### 1. 点击链路日志

- 新增轻量本地日志模块，使用 `wx` 本地缓存保存最近 80 条记录。
- 每条记录包含：
  - `time`：本地时间；
  - `event`：事件名；
  - `message`：大白话说明；
  - `route`：目标页面；
  - `durationMs`：跳转耗时（有则记录）；
  - `error`：失败信息（有则记录）。
- 工作台记录这些节点：
  - 点击“开始新创作”；
  - 弹出草稿确认；
  - 清除草稿；
  - 开始跳转；
  - `redirectTo` 成功；
  - `redirectTo` 失败并改用 `reLaunch`；
  - 最终失败。
- 工作台增加“点击链路日志”入口，支持：
  - 展开/收起；
  - 复制日志；
  - 清空日志。
- 日志只保存在当前设备，不上传照片、API Key 或云端。

### 2. 一键刷新预览

- 新增 `scripts/refresh-preview.ps1`。
- 脚本执行顺序：
  1. 读取 `config.js` 当前版本；
  2. 执行工程静态检查；
  3. 执行正式 ZIP 打包；
  4. 调用微信开发者工具 CLI 的 `preview`；
  5. 将二维码和预览信息写到项目上级目录。
- 输出文件命名：
  - `wechat-miniapp-preview-vX.Y.Z-qr.png`
  - `wechat-miniapp-preview-vX.Y.Z-info.json`
- 重复执行同一版本时覆盖同名预览产物，避免目录里堆积失效二维码。
- 脚本失败时停止，不生成“看起来成功”的二维码。

## 错误处理

- 日志写入失败不影响正常点击和跳转，只写控制台警告。
- 复制日志失败时给出明确 Toast。
- 预览脚本找不到微信开发者工具 CLI、工程检查失败或预览失败时返回非零退出码，并保留原有产物。

## 验收标准

- 点击“开始新创作”后，日志中能看到点击和跳转结果。
- 模拟 `redirectTo` 成功、失败后 `reLaunch`、最终失败三条路径，日志字段完整。
- 小程序静态检查和现有 smoke tests 全部通过。
- 运行一键脚本能生成有效 ZIP、PNG 二维码和 JSON 信息文件。
- 正式 ZIP 不包含 `node_modules`、`.wasm` 和敏感 Key。
