# 图片双指缩放时页面跟随滚动修复设计

## 1. 问题与目标

在主图编辑区域进行双指捏合缩放或双指平移时，当前页面外层也会跟着上下移动，导致图片位置不稳定、操作像“屏幕一直在动”。

本次修复目标：

1. 双指捏合仍然可以缩放图片。
2. 图片放大后，双指仍然可以在图片区域内平移。
3. 双指操作期间禁止页面整体滚动和下拉刷新。
4. 单指画红圈行为保持不变。
5. 手指全部离开后恢复页面正常滚动。
6. 不改变红圈坐标、图片导出和自动贴脸逻辑。

## 2. 推荐方案：局部手势期间锁住页面滚动

保留现有 `canvas-viewport`、`canvas-stage` 和 `canvas-gesture.js` 的缩放计算，只增加一层“页面滚动锁”状态。

### 组件职责

- `pages/index/index.wxml`
  - 继续在图片视口上捕获 `touchstart/touchmove/touchend/touchcancel`。
  - 在页面根节点前增加 `<page-meta>`，用 `page-style` 动态切换 `overflow: hidden`。
- `pages/index/index.js`
  - 新增 `pageScrollLocked` 数据状态。
  - 新增统一的 `setPageScrollLock(locked)` 方法，避免不同退出路径漏解锁。
  - 双指手势开始或首次识别为双指时锁滚动。
  - 双指结束、取消、页面卸载时解除锁定。
  - 单指画圈不主动锁页面，避免影响原有操作。
- `utils/canvas-gesture.js`
  - 保持现有缩放、偏移和触摸坐标换算逻辑不变，避免引入坐标回归。

页面滚动锁使用微信小程序页面自身的 `page-meta` 控制。图片区域现有的 `catchtouchmove` 继续作为事件兜底，不改动缩放算法，也不额外引入 CSS 手势方案。

## 3. 手势数据流

1. `onCanvasTouchStart` 读取当前视口内触摸点。
2. 触摸点达到两个时：
   - 清理单指画圈临时状态；
   - 设置手势模式为 `pinch`；
   - 调用 `setPageScrollLock(true)`，让 `<page-meta>` 应用 `overflow: hidden`；
   - 创建当前缩放基准。
3. `onCanvasTouchMove` 在双指状态下只更新图片缩放和偏移，不创建红圈。
4. `onCanvasTouchEnd` 或 `onCanvasTouchCancel`：
   - 清理 pinch 状态；
   - 调用 `setPageScrollLock(false)`，恢复页面滚动；
   - 保留最终图片视图。
5. `onUnload` 强制解除锁，避免页面异常退出后影响下一页。

## 4. 边界与错误处理

- 触摸点坐标缺失时，不更新图片视图，也不改变现有缩放值。
- 缩放值和偏移继续由 `canvas-gesture.js` 做边界限制。
- 双指过程中一根手指先离开时，不把剩余手指误判为新的单指画圈起点。
- 页面卸载、触摸取消、异常中断都执行解锁。
- 不改变主图清除、重新选择主图和页面切换时的视图重置行为。
- `page-meta` 的初始状态固定为未锁定，避免从其他页面返回时继承锁定状态。

## 5. 验证方案

### 自动验证

- 运行现有 `scripts/canvas-gesture-smoke.js`。
- 运行项目现有 `scripts/validate.js`。
- 新增或扩展静态检查，确认：
  - 双指开始、移动、结束、取消路径都有锁定/解锁；
  - 单指画圈仍然存在；
  - 不会把 `pageScrollLocked` 永久留在 `true`。

### 手工验证

在微信开发者工具或真机上验证：

1. 主图未放大时双指捏合，图片缩放，页面不滚动。
2. 放大后双指拖动，图片平移，页面不滚动。
3. 单指拖动，仍能正常画红圈。
4. 双指缩放中松开一根手指，再松开另一根，页面恢复滚动。
5. 触摸取消或切页后重新进入，页面没有残留锁定。

## 6. 范围控制

本次只修主图编辑区域的触摸冲突，不改动：

- 图片上传和压缩；
- 红圈导出；
- 云函数；
- AI 分析和生图；
- 其他页面的滚动行为。
