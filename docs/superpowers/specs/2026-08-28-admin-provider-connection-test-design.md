# 管理员配置保存提示与服务商真实连接测试设计

## 目标

在管理员配置页增加两项能力：

1. 保存全部配置后，明确告诉管理员保存成功或失败。
2. 在人脸识别、图片分析、主生图、备用生图、视频五个配置区域，对当前选中的服务商执行一次后台真实连接测试。

普通用户端、普通生图流程、腾讯换脸流程、额度扣除逻辑和制作记录不改。

## 当前实现基础

- 管理员页已经有五个独立服务商档案区域：
  - `face`
  - `analysis`
  - `image`
  - `imageBackup`
  - `video`
- 每个区域已有服务商下拉框、模型和接口参数编辑。
- 管理员页已有模型探测入口 `probeModels`，但它不能统一表达五个区域的“当前配置真实连接测试”。
- 云函数已经有管理员权限判断、运行配置读取、配置保存和错误格式化能力。

## 页面设计

### 保存提示

- 点击“保存全部配置”后，按钮进入“保存中...”状态，继续禁止重复点击。
- 保存成功：
  - 页面顶部状态文字显示“配置已保存，当前配置已生效”；
  - 弹出一次成功提示；
  - 保留当前编辑区域和表单内容，不强制收起。
- 保存失败：
  - 页面状态文字显示“保存失败，旧配置未被覆盖”；
  - 弹出失败提示并显示可读原因；
  - 不清空用户刚刚填写的内容。
- 原有字段校验失败仍在前端拦截，不发送保存请求，也不显示“保存成功”。

### 测试入口

每个配置区域的工具栏增加“测试连接”入口；按钮只测试该区域当前下拉框选中的服务商档案。

五个入口分别对应：

- 人脸识别：测试当前视觉接口、模型和 Key。
- 图片分析：测试当前分析接口、模型和 Key。
- 主生图：测试当前主生图接口、模型和编辑参数。
- 备用生图：测试当前备用生图接口、模型和编辑参数。
- 视频：测试当前视频接口、模型和创建/查询参数。

测试过程中按钮显示“测试中...”，同一时间只允许一个管理员连接测试，避免重复请求。

## 后台接口设计

新增云函数 action：

```js
{
  action: "testAdminProviderConnection",
  section: "face" | "analysis" | "image" | "imageBackup" | "video",
  providerId: "当前服务商 ID",
  requestId: "admin-connection-test-..."
}
```

前端只提交区域和服务商 ID，不把 Key 作为请求参数传回云函数。云函数从管理员运行配置中读取对应档案，重新确认当前管理员权限后再发起测试。

返回统一结构：

```js
{
  ok: true,
  section,
  provider,
  model,
  durationMs,
  message
}
```

失败时返回：

```js
{
  ok: false,
  errorCode,
  section,
  provider,
  model,
  durationMs,
  message
}
```

返回内容只包含服务商、模型、耗时和可读错误原因，不返回 API Key、请求头、完整请求体或上游敏感响应。

## 真实调用策略

### 通用顺序

1. 校验管理员权限。
2. 读取最新运行配置，绕过短缓存，避免测试旧参数。
3. 找到指定区域和服务商档案。
4. 校验接口地址、模型和 Key 是否完整。
5. 按服务商协议发送最小真实请求。
6. 将上游 HTTP 状态和错误映射成中文结果。
7. 返回耗时和结果，不创建制作记录、不扣小程序额度。

### 请求选择

- OpenAI 兼容服务商优先调用模型检查/模型列表能力，用于验证地址、鉴权和模型可见性。
- 如果服务商没有可用的轻量检查接口，则调用该服务商支持的最低成本真实请求，避免生成正式图片或视频。
- 视频接口优先验证创建接口和查询接口配置；不提交正式视频任务。
- 腾讯人脸融合配置不复用这五个通用服务商测试按钮，继续使用现有腾讯专项测试入口。

### 费用说明

测试不扣小程序额度，不写制作记录，也不进入普通生图计费流程。但如果某个第三方服务商把鉴权或最小请求本身计费，页面的结果文案会明确提示“第三方平台可能产生费用”，不伪称所有上游都零费用。

## 配置与安全边界

- 不改现有服务商档案保存格式。
- 不改管理员页面已有的 Key 显示规则。
- 测试请求只在云函数后台使用已保存 Key。
- Key 不进入前端测试请求参数、返回值、日志、审计日志、发布包或测试输出。
- 上游完整错误正文只在云函数内部做解析；对管理员只返回脱敏后的可读原因。
- requestId 用于防止同一次点击的重复处理，但连接测试不扣额度，因此不创建额度退款分支。

## 错误展示

统一把错误分为：

- 配置不完整：接口地址、模型或 Key 缺失。
- 身份验证失败：Key 无效、无权限或过期。
- 地址错误：域名、路径或协议不正确。
- 模型错误：模型不存在或当前账号无权使用。
- 网络错误：连接失败、DNS 失败或上游不可达。
- 超时：在配置的超时时间内没有返回。
- 上游错误：服务商返回 4xx/5xx。

页面显示短句；详细上游响应不直接展示，避免把密钥、内部地址或大段错误文本带到前端。

## 测试验收

新增或调整专项 smoke test，至少覆盖：

1. 五个区域都有“测试连接”入口。
2. 点击测试时使用当前服务商档案，而不是旧的主配置。
3. 前端请求不携带 API Key。
4. 非管理员调用被拒绝。
5. 配置缺失时不发上游请求并返回明确原因。
6. 成功结果包含区域、服务商、模型和耗时。
7. 失败结果不返回 Key、请求头或完整上游响应。
8. 保存成功显示成功提示，保存失败保留表单并显示失败原因。
9. 测试连接不扣小程序额度、不新增制作记录。
10. 普通生图、备用生图、腾讯换脸和视频流程的原有测试继续通过。

## 版本与发布

实现完成后按功能升级版本：

```text
0.53.0 → 0.54.0
```

执行顺序：

1. 运行专项 smoke test 和全量校验。
2. 从干净发布副本正式打包。
3. 通过受控同步脚本同步 GitHub `main`。
4. 从合并后的 `main` 部署 `api` 云函数。
5. 做线上只读版本、构建标记、依赖和健康检查。
6. 保留现有并行工作区，不覆盖无关改动。
