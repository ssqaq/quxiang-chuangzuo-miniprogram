# 照片转视频闲置文件自动清理设计

日期：2026-08-24

## 1. 目标

照片转视频产生的源照片和临时结果视频，不再只依赖每天凌晨 3 点的清理。

新增规则：

1. 用户离开照片转视频页面或小程序进入后台后，记录本次使用结束时间；
2. 离开满 2 小时后，云端删除本次登记的照片转视频临时源照片、临时结果视频，
   以及这两类文件对应的临时登记记录；
3. 云端定时器每 15 分钟检查一次，保证“满 2 小时”不会长期等待；
4. 每天凌晨 3 点继续执行超过 72 小时的兜底清理；
5. 已保存到用户相册的文件、正式制作记录和正式结果图绝不进入这套临时文件清理。

## 2. 范围和边界

只处理集合 `photo_to_video_temp_assets` 中登记的两种文件：

- `kind: "source"`：上传给视频服务的源照片；
- `kind: "result"`：视频服务返回的临时结果视频。

这里说的“照片记录”，是这张临时源照片在
`photo_to_video_temp_assets` 中的登记记录，不是用户的正式制作记录。

不处理：

- 用户相册里的本地文件；
- 正式制作记录；
- 正式结果图；
- 非照片转视频功能产生的云文件；
- 没有登记到临时文件集合的云文件。

“关闭小程序”按微信小程序可可靠感知的生命周期处理：页面 `onHide`、页面
`onUnload` 或 App `onHide` 触发时，向云端登记本次使用结束时间。生命周期回调
可能因系统强杀而不触发，因此 72 小时兜底规则必须保留。

## 3. 数据设计

在 `photo_to_video_temp_assets` 文档中增加以下字段：

- `ownerOpenId`：登记文件的用户；
- `sessionId`：本次照片转视频使用会话；
- `lastActiveAt`：最近一次使用时间；
- `closedAt`：客户端报告离开时间；
- `idleCleanupAfter`：`closedAt + 2 小时`；
- `cleanupAfter`：登记时间加 72 小时的最终兜底时间；
- `status`：`pending`、`failed` 或清理中的状态；
- `attempts`、`lastError`、`updatedAt`：失败重试和诊断字段。

同一 `fileID + kind` 继续使用幂等文档 ID，避免页面重复登记造成重复删除。

## 4. 清理流程

### 4.1 客户端

照片转视频页面显示、上传、创建任务、轮询或预览期间，客户端会发送一次
“仍在使用”状态，更新对应登记的 `lastActiveAt`；重新回到页面时也会先发送
一次活跃状态。这样用户只是暂时切到后台又回来时，不会因为旧的 `closedAt`
而被误删。

照片转视频页面进入后台或销毁时：

1. 停止轮询、结束计时器和视频预览；
2. 保留已有清理队列，不能因为页面隐藏而丢失；
3. 调用云函数报告本次会话结束；
4. 云调用失败不阻塞页面退出，也不能弹窗打扰用户；
5. 本地临时文件继续走本地清理队列，重新进入页面时再次兜底。

客户端只发送会话结束信号，不直接删除云文件，不传入任意文件路径。

### 4.2 云函数

新增一个受限的会话结束接口，只更新该用户自己名下、已登记的临时文件：

- 校验用户身份；
- 校验 `sessionId`；
- 将匹配文件的 `closedAt` 更新为当前时间；
- 计算并写入 `idleCleanupAfter`；
- 不允许客户端修改 `fileID`、`kind`、`ownerOpenId` 或 `cleanupAfter`。

客户端活跃状态使用独立的受限接口，只允许更新当前用户自己名下、已登记的
临时文件的 `lastActiveAt`，不能延长 `cleanupAfter`，也不能把文件从清理队列
中永久移除。

清理入口统一由定时触发器调用：

1. 先处理 `idleCleanupAfter <= now` 的闲置文件；
2. 再处理 `cleanupAfter <= now` 的 72 小时兜底文件；
3. 每批最多处理 100 条；
4. 删除成功或云文件已不存在时，移除登记；
5. 删除失败保留登记、递增 `attempts`、记录 `lastError`，下次继续；
6. 同一文件只允许 `source` 或 `result` 两种登记类型。

只有云文件删除成功，或确认云文件已经不存在时，才删除对应的临时登记记录；
如果删除失败，必须保留记录等待下一轮重试。

定时器改为每 15 分钟运行一次。每天凌晨 3 点由同一个清理入口继续执行，
因此不会丢掉原有的 72 小时兜底能力。

## 5. 并发和误删保护

- `onHide`、`onUnload`、重复进入后台可能重复上报，接口必须幂等；
- 重新回到页面并继续使用时，客户端可以发送活跃时间，清理任务必须跳过
  `lastActiveAt` 在最近 2 小时内更新的文件；
- 正在运行的视频任务不报告关闭完成，避免用户切后台后任务刚结束就被删除；
- 只有集合中登记的 `source/result` 文件允许被清理；
- 72 小时规则优先作为最终上限，不因为客户端时间异常而延长；
- 清理失败不能删除数据库登记，避免形成“文件还在但没有追踪记录”。

## 6. 测试范围

新增或补充测试覆盖：

1. `closedAt + 2 小时` 到期前不删除；
2. 到期后删除 source 和 result；
3. 未报告关闭的文件仍按 72 小时兜底；
4. 页面重复 `onHide/onUnload` 不重复登记；
5. 页面重新活跃后不会误删；
6. 删除失败会保留记录并重试；
7. 正式记录、结果图和非照片转视频文件不会被清理；
8. 定时触发配置为每 15 分钟；
9. 72 小时旧规则仍可单独验证；
10. 无微信身份、无效会话和非法文件类型会被拒绝。

## 7. 验收标准

- 用户离开照片转视频页面 2 小时后，已登记的临时源照片和临时结果视频会被云端清理；
- 进入后台后重新回来继续使用，不会清理仍在使用的文件；
- 页面退出不会因为上报失败卡住或弹窗；
- 每天凌晨 3 点的 72 小时兜底规则仍然存在；
- 本地静态校验、照片转视频 smoke、清理专项 smoke 和全量 smoke 全部通过；
- 正式 ZIP 包含云函数配置、客户端改动、测试和 README；
