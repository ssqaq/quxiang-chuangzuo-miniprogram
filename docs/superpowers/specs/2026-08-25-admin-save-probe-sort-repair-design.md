# 管理员保存后探测、模型排序与修复建议设计

## 目标

在管理员模型配置页补充三项体验：

1. 保存全部配置成功后自动测试四套模型接口。
2. 获取模型后按模型名称自然排序。
3. 连接失败时同时告诉管理员应该怎么修复。

## 设计

### 保存后自动测试

- 保存请求成功后，先更新页面配置和版本信息。
- 页面提示已保存并开始自动测试。
- 自动调用现有四套模型探测接口，不增加新的后台接口。
- 探测完成后复用现有探测结果区域，显示正常数量、每套模型状态和失败原因。
- 保存失败时不触发探测。

### 模型名称排序

- 获取模型后在管理员页统一去重并排序。
- 使用不区分大小写的自然排序，让 `model-2` 排在 `model-10` 前面。
- 搜索在排序后的完整列表上进行。

### 连接失败修复建议

- 未配置：补齐 Provider、接口地址、API Key 和模型。
- 密钥异常：重新填写 API Key，并确认权限。
- 模型不存在：重新获取模型并选择列表中的模型。
- 接口不支持：改用兼容接口根地址，不要填聊天完成地址。
- 上游异常：检查 HTTP 状态和服务商状态。
- 网络异常：检查域名、地址、网络和服务是否在线。

## 验证

- 管理员页、云函数 JavaScript 语法检查。
- 保存后自动探测专项测试。
- 模型自然排序和搜索专项测试。
- 常见连接失败原因与修复建议测试。
- 静态检查、正式打包和 GitHub 同步。
