# 管理员服务商中文名称、筛选与自动检查设计

## 1. 目标

在现有管理员“模型、积分与成本配置”页面增加三项能力：

1. 服务商中文名称可以直接在后台修改并保存到 CloudBase；
2. 模型配置卡片和模型探测结果可以按服务商筛选；
3. 保存配置时自动检查所有已使用服务商是否都有合格的中文名称。

页面显示中文名称，但调用上游接口、保存模型配置和统计归类仍使用原英文标识。API Key、AppSecret 和完整敏感地址不进入服务商名称配置，也不写入新增日志。

## 2. 当前情况

- 管理员页面目前使用前端常量把 `xingju`、`lingyun`、`dashscope` 显示为“星炬”“凌云”“阿里云百炼”。
- 中文名称不能从后台修改，增加服务商时必须修改源码。
- “获取模型”每次只请求当前配置中的一个服务商，因此在模型选择弹窗内增加服务商筛选没有实际意义。
- 管理员配置保存在现有 CloudBase 管理员运行时配置文档中，适合继续保存服务商中文名称，不需要新增集合或服务器。

## 3. 数据设计

在现有管理员运行时配置顶层增加：

```js
providerLabels: {
  xingju: "星炬",
  lingyun: "凌云",
  dashscope: "阿里云百炼"
}
```

规则：

- Key 是调用接口时使用的真实服务商标识；
- Value 是管理员页面展示的中文名称；
- 内置三项作为默认值，旧配置读取时自动补齐；
- 自定义服务商保留原标识，不改写接口参数；
- 保存时只接受普通短文本，不接受对象、数组或超长内容；
- 中文名称去除首尾空格，长度为 1～20 个字符，并且至少包含一个中文字符；
- 服务商标识长度不超过 120 个字符；
- 不允许使用 `__proto__`、`prototype`、`constructor` 等危险键名。

不新增数据库集合。`providerLabels` 跟随现有管理员配置一起完成读取、合并、版本递增和审计。

## 4. 中文名称后台配置

### 4.1 页面入口

在模型配置入口增加“服务商名称”卡片。该卡片始终显示，不受服务商筛选影响。

进入后显示服务商名称列表：

| 服务商标识 | 中文名称 |
|---|---|
| `dashscope` | 阿里云百炼 |
| `xingju` | 星炬 |
| `lingyun` | 凌云 |

列表来源是以下内容的并集：

- 三个内置服务商；
- 人脸识别、图片分析、生图主模型、生图备用模型、视频模型当前使用的服务商；
- 已经保存到 `providerLabels` 的自定义服务商。

英文标识只读，中文名称可编辑。管理员在任一模型配置里输入新的英文服务商标识后，名称列表立即补出一行空白中文名称，方便继续填写。

### 4.2 显示与传参

- 页面输入框、配置摘要、模型探测和失败统计优先显示 `providerLabels` 中的中文名称；
- 保存模型配置、测试连接、获取模型和探测模型前，根据中文名称反查真实英文标识；
- 自定义中文名称修改后，页面中对应服务商的显示同步更新；
- 未知服务商在补齐中文名称前仍显示原标识，并显示明确的待补提示。

## 5. 服务商筛选

### 5.1 筛选位置

筛选放在管理员模型配置入口区，而不是“获取模型”弹窗。原因是模型弹窗每次只读取一个服务商，本身没有跨服务商列表可筛选。

筛选项根据当前配置动态生成：

```text
全部 / 阿里云百炼 / 星炬 / 凌云 / 其他已配置服务商
```

### 5.2 筛选范围

选择某个服务商后：

- 只显示属于该服务商的人脸、图片分析、生图主模型、生图备用模型、视频模型入口卡片；
- 四套模型接口探测结果只显示匹配项；
- “服务商名称”入口始终保留；
- 筛选只改变页面展示，不修改配置、不触发接口调用；
- 如果当前打开的配置编辑区不属于新筛选条件，自动关闭该编辑区，避免出现“入口隐藏但编辑器还开着”的错乱状态；
- 筛选值只保存在当前页面内，重新进入管理员页面默认恢复“全部”。

## 6. 中文名称自动检查

### 6.1 前端检查

点击“保存全部配置”前，收集五套模型当前使用的真实服务商标识并检查：

- 是否存在对应中文名称；
- 中文名称是否至少包含一个中文字符；
- 长度是否符合限制。

失败时不发送保存请求，自动打开“服务商名称”配置区，并显示例如：

```text
服务商 new-provider 还没有中文名称，请先填写。
```

对应输入行显示错误状态。

### 6.2 云函数检查

云函数不能只相信前端。在合并旧配置和本次修改后再次执行同样检查：

- 防止旧版小程序或手工调用绕过前端；
- 已知服务商自动使用内置默认中文名称；
- 自定义英文服务商缺少中文名称时返回 `ADMIN_PROVIDER_LABEL_REQUIRED`；
- 返回内容只包含服务商标识和字段错误，不包含 API Key 或其他秘密。

## 7. 后端兼容

需要把 `providerLabels` 接入现有流程：

- `normalizeRuntimePatch`：只复制和清洗允许的名称映射；
- `validateRuntimePatch`：检查映射格式、长度、中文字符和危险键名；
- `mergeRuntimeConfig`：增量合并名称，不因一次保存删除其他名称；
- `redactConfig` / `adminConfigView`：向管理员返回名称映射；
- `resolveEffectiveConfigs`：旧配置自动合并内置默认名称；
- `saveAdminConfig`：把名称写回现有管理员运行时配置文档；
- 管理员配置审计：记录名称字段发生变化，但继续对 API Key 做脱敏。

老配置没有 `providerLabels` 时继续正常加载，三项内置中文名称自动出现。现有模型执行、成本统计、失败切换和质量能力判断继续使用英文服务商标识，不改变行为。

## 8. 页面状态与错误处理

前端新增状态：

- `providerLabelRows`：服务商名称编辑行；
- `providerLabelErrors`：每个服务商对应的错误文字；
- `providerFilterOptions`：动态筛选选项；
- `providerFilterValue` / `providerFilterIndex`：当前筛选；
- `providerSectionVisibility`：五套配置入口是否显示；
- `filteredModelProbeResults`：筛选后的模型探测结果。

错误处理：

- 中文名称为空或不含中文：阻止保存并指出具体服务商；
- 云函数拒绝：沿用管理员页面现有错误弹窗，展示清晰中文原因；
- 旧配置读取失败：保留内置三项，不影响管理员修复其他配置；
- 自定义服务商删除后：已经保存的中文名称继续保留，避免历史统计重新显示英文。

## 9. 测试

### 9.1 前端专项测试

- 老配置自动得到三个内置中文名称；
- 修改 `lingyun` 中文名称后，相关配置摘要同步更新；
- 保存、测试连接、获取模型、模型探测仍发送 `lingyun`；
- 新增 `custom-provider` 后自动出现中文名称编辑行；
- 中文名称为空、纯英文或超长时阻止保存；
- 选择“凌云”后只显示对应配置卡片和探测结果；
- 切换筛选时不修改实际表单配置；
- 未知、自定义服务商兼容。

### 9.2 云函数专项测试

- `providerLabels` 正常清洗、合并、保存和返回；
- 旧配置自动合并默认名称；
- 自定义英文服务商缺少中文名称时拒绝保存；
- 危险键名、非对象、超长标识、超长中文名称被拒绝；
- API Key 继续脱敏，新增日志不包含秘密；
- 管理员配置审计能识别名称修改。

### 9.3 总验证

- 页面 JavaScript 语法检查；
- 管理员加载、布局、配置保存专项 smoke test；
- `node scripts/validate.js`；
- `git diff --check`；
- 正式发布包清单和二维码真机预览检查。

## 10. 发布

这是新增后台功能，版本按次版本升级。代码和测试完成后：

1. 更新小程序、API 云函数、媒体 Worker 和水印网关的统一版本号；
2. 通过受控同步脚本提交并推送 GitHub；
3. 从最终提交生成正式 ZIP 和发布记录；
4. 生成同版本预览二维码；
5. 若云函数代码发生变化，部署并核对线上构建版本与标记；
6. 明确报告 ZIP、提交 SHA、二维码和云函数是否真正上线。

## 11. 不在本次范围

- 不把多个服务商的 `/models` 接口聚合成一个跨服务商模型市场；
- 不新增独立服务器或数据库集合；
- 不修改用户端生成流程；
- 不修改已有上游 API Key；
- 不把服务商中文名称用于成本归类或接口路由。
