# 三类模型真实成本统计设计

## 目标

在现有管理员“模型用量统计”里增加每日预计成本统计，所有价格统一按人民币元计算，并尽量使用供应商返回的真实用量；供应商没有返回完整用量时，按已配置的分辨率、视频时长和价格做可追溯的估算。

需要覆盖：

- 人脸识别：输入 Token、输出 Token、总 Token、输入费用、输出费用；
- 生图：1K、2K、4K 分辨率、调用次数和费用；
- 视频：480p、720p、1080p 分辨率、实际秒数和费用；
- 今日、最近 7 天、最近 30 天的总成本和分类成本。
- 按用户统计用量；
- 按 Provider 和模型名称分组；
- 导出 Excel；
- 最近 12 个月月度统计。

## 计费口径

### 人脸识别

默认模型为 `qwen3-vl-flash`，价格配置为：

- 输入：0.15 元 / 百万 Token；
- 输出：1.5 元 / 百万 Token；

费用公式：

```text
输入费用 = 输入 Token ÷ 1,000,000 × 输入单价
输出费用 = 输出 Token ÷ 1,000,000 × 输出单价
人脸识别费用 = 输入费用 + 输出费用
```

优先从上游响应的 `usage.prompt_tokens`、`usage.completion_tokens`、`usage.total_tokens` 读取。没有返回 Token 时，事件保留调用次数，但金额标记为“未计算”，不根据图片大小硬猜 Token。

### 生图

默认价格配置为：

- 1K：0.015 元 / 张；
- 2K：0.025 元 / 张；
- 4K：0.035 元 / 张。

优先读取请求或管理员有效配置里的尺寸，并统一映射成 1K、2K、4K。当前 `1024x1024` 映射为 1K；无法识别的尺寸按当前生图价格配置里的默认档位处理，并保存估算标记。

### 视频

默认价格配置为：

- 480p：0.2 元 / 秒；
- 720p：0.3 元 / 秒；
- 1080p：1.8 元 / 秒。

费用公式：

```text
视频费用 = 视频秒数 × 当前分辨率每秒单价
```

视频秒数优先读取上游返回值，其次读取创建请求里的 `duration`；如果两者都没有，使用当前任务配置的默认时长，并标记为估算。

视频创建请求计入一次成本事件，视频查询轮询不计入。创建失败但已实际发往上游的请求仍计入供应商成本统计，避免漏算。

## 配置结构

在现有 `admin_runtime_config` 增加 `costs` 配置，不把价格写死在页面或统计函数里：

```js
{
  currency: "CNY",
  face: {
    inputPerMillionTokens: 0.15,
    outputPerMillionTokens: 1.5
  },
  image: {
    defaultResolution: "1K",
    perImage: {
      "1K": 0.015,
      "2K": 0.025,
      "4K": 0.035
    }
  },
  video: {
    defaultResolution: "720p",
    perSecond: {
      "480p": 0.2,
      "720p": 0.3,
      "1080p": 1.8
    },
    defaultDurationSeconds: 3
  }
}
```

管理员页增加“模型成本配置”区域，可以修改以上价格和默认值。服务端保存前校验：

- 所有价格必须是 0 或正数；
- Token 单价、图片单价和视频单价限制合理上限；
- 分辨率只能使用支持的档位；
- 默认视频时长必须大于 0。

## 数据结构

继续使用 `model_usage_events`，在原有调用信息上增加成本字段：

- `currency`
- `billingSource`: `actual`、`estimated`、`unavailable`
- `inputTokens`
- `outputTokens`
- `totalTokens`
- `imageResolution`
- `videoResolution`
- `videoDurationSeconds`
- `unitPrice`
- `estimatedCost`
- `costBreakdown`
- `costConfigVersion`

其中：

- `actual` 表示用量来自供应商响应；
- `estimated` 表示使用请求参数或默认配置计算；
- `unavailable` 表示无法计算金额；
- `estimatedCost` 统一保存人民币元数值；
- `costBreakdown` 保存输入、输出、图片或视频秒数等明细，方便后台解释金额。

旧事件没有这些字段时，次数继续参与原统计，金额和 Token 显示为“历史数据无法计算”，不伪造历史成本。

## 服务端接口

扩展管理员 `getModelUsageStats` 返回：

- 原有调用次数、成功数、失败数；
- `costSummary`：今天、最近 7 天、最近 30 天的总成本、已计算成本、未计算事件数；
- `costByType`：生图、人脸识别、视频的成本、Token 和视频秒数；
- `daily`：每天的成本、Token、生图分辨率明细、视频分辨率和秒数明细；
- `models`：模型、供应商、调用数和成本；
- `pricing`：当前生效的人民币价格配置。
- `users`：按脱敏用户哈希汇总调用次数、成本、Token 和视频秒数；
- `monthly`：最近 12 个月按月份汇总调用次数、成本、Token 和视频秒数。

新增管理员 action：`exportModelUsageStats`。

该接口复用相同统计口径，生成一个 `.xlsx` 文件并上传到云存储，文件包含：

- `每日明细`
- `按用户`
- `按模型`
- `按月份`

返回云文件 ID，管理员端下载后使用微信的文档预览打开。用户分组只保存
`sha256(usage-user:<OpenID>)` 的前 12 位，不在统计事件里保存真实 OpenID。

只有实际发起管理员统计请求的管理员可以读取和保存成本配置，普通用户继续返回无权限。

## 管理员页面

在现有统计卡片内增加：

1. 顶部三组汇总：
   - 今日预计成本；
   - 最近 7 天预计成本；
   - 最近 30 天预计成本。

2. 三类模型卡片：
   - 人脸识别：Token、已计算金额、未计算次数；
   - 生图：1K/2K/4K 张数和金额；
   - 视频：各分辨率秒数和金额。

3. 每日明细：
   - 日期；
   - 预计成本；
   - 生图、人脸、视频分类成本；
   - Token 总量；
   - 视频总秒数；
   - 未计算数量。

4. 额外统计：
   - 按用户显示用量最多的用户哈希；
   - 按 Provider / 模型显示调用量和成本；
   - 按月份显示最近 12 个月趋势；
   - 提供“导出 Excel”按钮。

金额旁显示“实际”或“估算”，当日存在未计算事件时同时显示提示，避免把不完整金额误认为供应商账单。

## 错误处理和兼容

- 上游响应没有 `usage` 时不影响模型功能，只将该事件标记为估算或未计算；
- 供应商返回异常 Token、负数秒数或未知分辨率时，忽略异常字段并使用安全回退；
- 成本统计读取失败不影响生图、人脸识别和视频功能；
- 价格配置缺失时使用代码默认人民币价格，并在后台提示“使用默认价格”；
- 不保存 API Key、提示词、图片 fileID、用户 OpenID 或素材内容。

## 验证

新增专项测试覆盖：

- 人脸 Token 费用公式和输入/输出拆分；
- 生图 1K、2K、4K 映射和费用；
- 视频不同分辨率、不同秒数的费用；
- 实际用量优先、估算回退和无法计算状态；
- 北京时间日期聚合；
- 旧事件不报错且金额显示历史数据无法计算；
- 视频查询轮询不产生成本事件；
- 非管理员不能读取或修改成本配置；
- 统计页面能显示金额、Token、视频秒数和分辨率明细。
