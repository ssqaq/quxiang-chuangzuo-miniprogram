# 完整局部修正页实施计划

## 目标

在不覆盖原制作记录的前提下，交付可用的完整局部修正页，并确保修正请求沿用图片生成的积分预留、并发幂等、失败退款和操作状态机。

## 实施步骤

### 1. 页面入口与记录加载

- 核对 `app.json` 已登记 `pages/repair/repair`。
- 核对制作结果页、工作台和制作记录页只对有效云端图片显示“局部修正”入口。
- 页面通过 `recordId` 加载记录，拒绝本地记录、墓碑记录和缺少结果图的记录。

### 2. 完整修正编辑页

- 在结果图上重新拖动红圈并导出 mask。
- 支持重新选择主图，补选或移除人脸、穿搭参考。
- 问题项由 JS 预计算勾选状态，避免依赖 WXML 不兼容表达式。
- “红圈外内容被改动”始终强制保留。
- 删除最后一张穿搭参考后立即隐藏依赖穿搭的问题项，并清理失效选择。
- 成功和失败使用独立状态，成功后不再被 `finally` 覆盖。

### 3. 云端安全与一致性

- `repairImage` 独立校验请求类型、父记录归属、父记录有效性、来源文件一致性和素材登记。
- 修正链最多 10 次，第 10 次允许，第 11 次拒绝。
- 事务内只做额度预留、操作抢占和修正序号占位；供应商调用保持在事务外。
- 同一 `requestId` 只允许一个供应商执行者。
- 失败只退款一次，`refunded` 后原 `requestId` 永久禁止重试。
- 成功记录追加保存，写入父记录、根记录、修正序号和修正上下文。
- 父记录删除时保留墓碑，子修正版继续展示。

### 4. 自动验证

- 新增局部修正专项 smoke，覆盖问题项规范化、入口路由、本地记录、墓碑、mask、旧素材、第 10/11 次、并发、退款和父子记录。
- 运行页面语法检查、局部修正专项 smoke、生成并发 smoke、视频 smoke 和项目总验证。
- 修复所有失败后再升版。

### 5. 版本与交付

- 功能版本从 `0.20.0` 升到 `0.21.0`。
- 同步小程序配置、云函数版本、锁文件和部署标记。
- 生成正式发布包 `D:\aips小程序\wechat-miniapp-release-v0.21.0.zip`。
- 提交并推送 `origin/main`，确认本地和远端提交一致。
