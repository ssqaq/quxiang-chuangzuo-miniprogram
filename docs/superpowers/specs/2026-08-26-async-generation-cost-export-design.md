# 异步生图、孤儿图片清理、成本校验与明细导出设计

## 背景

当前普通生图请求在一次云函数调用内完成“预留积分 → 调用凌云 → 下载结果 → 上传云文件 → 写入生成记录 → 返回小程序”整条链路。

2026 年 8 月 26 日的真实测试中，凌云 `gpt-image-2` 生成 1K 图片约耗时 59 秒。模型已经生成并上传图片时，客户端或自动化调用可能已经超时，导致：

- 小程序没有拿到最终结果；
- `generation_operations` 仍停留在 `processing`；
- `generation_records` 没有对应记录；
- 已上传的结果图没有可靠的归属和清理路径；
- 用户再次点击时容易重复提交或重复等待。

本次改动同时覆盖用户已经确认的四项功能：

1. 普通生图改为异步任务，小程序提交后轮询；
2. 清理没有生成记录的孤儿图片和卡住任务；
3. 管理员成本价格输入校验；
4. 导出逐次模型调用成本明细；

并在不更换模型、不降低画质、不改变对外价格的前提下，减少素材处理和结果落库的外围等待。

## 目标

- 点击“生成”后快速返回任务已提交，不让页面被凌云的几十秒响应时间卡住。
- 后台只执行一次实际生图；重复提交同一个 `requestId` 不重复扣费、不重复调用上游。
- 生成成功后，小程序自动拿到图片并写入本地制作记录。
- 云函数中途超时、写记录失败或客户端退出时，任务仍可恢复。
- 失败任务自动退款，退款和清理操作可重复执行而不会重复退款。
- 图片和视频成本价格由同一份云端配置驱动，管理员修改后下拉框和统计立即使用新价格。
- 成本导出能看到每一次调用的脱敏明细，但不泄露密钥、OpenID 或完整隐私内容。
- 通过并行素材下载、并行素材校验和减少串行落库，尽量缩短模型调用前后的额外时间。

## 非目标

- 不更换凌云 provider 或 `gpt-image-2` 模型。
- 不修改 1K、2K、4K 对外价格：
  - 1K：¥0.06/张；
  - 2K：¥0.10/张；
  - 4K：¥0.15/张。
- 不降低输出画质，不修改现有尺寸比例规则。
- 不把任何 API Key 放到小程序端、任务文档或 Git。
- 本期只改普通 `generate` 生图主流程；`repairImage` 保持现有同步行为，沿用同一套幂等和成本记录基础能力，后续可单独迁移。
- 不把提示词、原始 OpenID、原始请求头等隐私或敏感数据放进成本导出。

## 方案选择

### 方案 A：现有 `api` 云函数内的队列 + 定时 worker + 前端轮询（采用）

普通 `generate` 请求只做参数校验、素材归属校验、积分预留和任务入队，立即返回 `requestId`。新增定时处理分支从 `generation_operations` 中抢占 `queued` 任务，调用现有凌云逻辑并保存结果。小程序用新增的状态查询 action 轮询。

优点：

- 复用现有 `generation_operations`、积分预留、成本事件和生成记录；
- 不需要把密钥暴露给前端；
- 改动集中，部署仍可沿用 `api` 云函数；
- 能覆盖客户端超时、页面退出、重复点击和孤儿结果。

代价：

- 任务启动会增加一个定时扫描周期以内的等待；
- worker 必须限制单次处理数量，并区分定时触发器，避免和旧清理逻辑串路。

### 方案 B：新增独立 `generation-worker` 云函数

由 API 函数入队，再异步唤起独立 worker。

优点是隔离清晰、后续扩展方便；代价是需要新增函数、部署配置、权限和运维链路。本期改动面过大，不采用。

### 方案 C：继续同步调用，只提高超时

改动最少，但用户仍需等待几十秒，自动化或客户端提前超时的问题仍然存在，也不能从根本上解决孤儿结果。不采用。

## 总体架构

### 组件职责

| 组件 | 职责 |
|---|---|
| `pages/index/index.js` | 准备素材、提交任务、显示排队/生成阶段、轮询并恢复结果 |
| `services/cloud.js` | 提供提交和状态查询封装，轮询请求不自动重试生图 |
| `cloudfunctions/api/index.js` | 校验、预留积分、入队、worker 处理、记录结果、退款、清理、成本导出 |
| `cloudfunctions/api/config.json` | 增加生图队列 worker 和任务回收触发器，并保留现有清理触发器 |
| `generation_operations` | 任务状态、输入快照、处理心跳、结果文件和幂等依据 |
| `generation_records` | 用户可见的正式生成记录 |
| `model_usage_events` | 每次上游模型调用的成本和耗时明细 |
| `pages/admin/admin.js` | 成本输入校验、价格显示和成本明细导出按钮状态 |

### 数据流

1. 小程序生成前完成本地素材准备和上传，拿到主图、mask、参考图的 `fileID`。
2. 小程序调用 `generate`，带上稳定的 `requestId` 和完整但经过限制的生图参数。
3. 云函数验证用户、素材归属、模型配置和成本配置。
4. 云函数在事务中预留积分并创建或复用 `generation_operations`，状态设为 `queued`。
5. 云函数立即返回任务编号、状态和扣费预留结果。
6. worker 原子抢占一个 `queued` 任务，状态改为 `processing`，记录 `processingAt` 和心跳。
7. worker 并行准备所需素材，调用凌云，下载并上传结果。
8. 上传成功后先把 `resultFileID` 写入 `generation_operations`，再写 `generation_records`。
9. 记录写入成功后，操作状态改为 `succeeded`，保存完整结果摘要。
10. 小程序轮询发现 `succeeded`，通过 `fileID` 或临时地址展示图片并保存本地记录。
11. 任何不可恢复错误都将任务标记为 `failed`，执行一次幂等退款，并清理已经上传的结果文件。

## 任务数据设计

继续使用 `generation_operations`，不新增任务集合。普通生图操作增加或统一以下字段：

| 字段 | 说明 |
|---|---|
| `_id` | 由用户和 `requestId` 派生，保证同一请求唯一 |
| `openid` | 仅云端使用，不返回给前端 |
| `requestId` | 客户端幂等编号 |
| `kind` | `image` |
| `status` | `reserved`、`queued`、`processing`、`succeeded`、`failed`、`refunding`、`refunded` |
| `payload` | 限制长度后的生图参数和用户素材 fileID，不包含密钥 |
| `pipelineStage` | `queued`、`validate`、`upstream`、`download`、`upload`、`record`、`succeeded` 或 `failed` |
| `queuedAt` | 入队时间 |
| `processingAt` | worker 抢占时间 |
| `lastHeartbeatAt` | worker 最近一次进度更新时间 |
| `attemptCount` | worker 尝试次数 |
| `resultFileID` | 结果上传后的云文件 ID，先于生成记录保存 |
| `resultTempFileURL` | 可选的临时地址缓存 |
| `recordId` | 正式生成记录 ID |
| `result` | 可安全返回给前端的结果摘要 |
| `lastError` | 脱敏错误码、短消息和是否可重试 |
| `expiresAt` | 任务最长保留时间 |
| `createdAt`、`updatedAt`、`succeededAt`、`failedAt` | 生命周期时间 |

任务中的 `payload` 只保留生成所需字段，并限制提示词和数组长度，避免文档无限增大。API Key 只从服务端现有配置读取，绝不从客户端 payload 接受。

## 云函数接口设计

### `generate`

普通生图改为“提交接口”，不再在用户请求内等待上游完成。

请求继续使用现有 `payload` 和 `requestId`。返回成功时至少包含：

```text
ok: true
requestId: string
taskId: string
status: "queued"
stage: "queued"
message: "生图任务已提交"
billing: 当前积分预留结果
```

同一 `requestId` 重复调用时：

- 已完成：直接返回原结果；
- 排队中或处理中：返回原任务状态；
- 已退款：返回明确的退款状态，不重新扣费；
- 不允许用同一编号提交另一种任务。

### `getGenerationStatus`

新增普通生图状态查询 action。请求只接受当前用户自己的 `requestId` 或 `taskId`，不触发凌云调用、不扣费、不重试上游。

返回字段：

```text
ok
requestId
taskId
status
stage
progress
message
result: { recordId, fileID, tempFileURL, record, billing }
error: { code, message }
queuedAt
processingAt
updatedAt
```

状态查询对不存在、已过期、已退款任务返回可读错误，不泄露其他用户任务信息。

### 定时 worker

在现有 `api` 云函数中增加明确的 `generation-queue-worker` 触发分支。每次触发：

1. 查询有限数量的 `queued` 任务；
2. 用事务逐个抢占，避免多个 worker 重复处理；
3. 单次只处理能在云函数时间限制内完成的任务；
4. 每个重要阶段更新心跳；
5. 当前任务完成或失败后再领取下一个任务。

worker 不复用“用户重复调用 `generate`”作为重试方式，而是调用抽出的内部处理函数，避免重复预留积分和重复进入入口校验。

现有 `isPhotoToVideoCleanupTrigger` 会把泛化的 `Timer` 识别为旧清理任务。新增 worker 后必须改为按 `triggerName` 精确分流；旧的照片转视频、诊断日志、水印和腾讯中间文件清理行为不能被改变。

## 生图处理和速度优化

### 保留不变的部分

- provider、模型、画质、尺寸规则和价格保持现状；
- 凌云上游请求仍使用现有幂等键；
- provider 重试只按现有服务端配置执行，不由前端轮询触发；
- 每个任务最多生成一次正式结果。

### 具体优化

1. **素材下载并行化**：主图、mask、脸部、服装和背景参考素材统一收集后用 `Promise.all` 并行下载，单个失败立即终止并记录阶段。
2. **素材归属校验并行化**：主图、mask 和各类参考素材的 `findUserAsset` 查询统一并行，保留每类数量上限。
3. **结果落库减少等待**：上传结果后立即写 `resultFileID`；获取临时地址、构造记录数据等可并行的步骤不再无谓串行。
4. **前端不再等待模型回包**：提交请求只等待入队，页面通过轮询获取完成状态。
5. **轮询节奏可控**：任务刚提交时较快查询，持续处理中逐步放宽间隔；页面隐藏时暂停，重新进入时立即恢复一次。
6. **本地恢复**：把未完成任务的 `requestId`、`taskId` 和最小展示信息保存到本地；页面重新打开时先恢复任务，再决定是否继续轮询。

这套优化能减少外围等待并消除“页面超时但后台已完成”的问题，但不能把凌云本身约 59 秒的模型计算变成几秒。

## 孤儿结果和卡住任务清理

新增任务回收逻辑，优先复用 `generation_operations`：

### 结果补救优先级

1. `resultFileID` 存在、`recordId` 为空：尝试按保存的输入快照补写 `generation_records`；
2. 记录补写成功：把 `recordId` 和结果写回 operation，标记 `succeeded`；
3. 结果文件存在但记录补写失败：保留文件和任务，增加重试次数，下一轮继续补救；
4. 超过保留时间仍无法补救：删除结果文件，标记失败并退款。

### 卡住任务

- `queued` 超过排队阈值：标记失败并退款；
- `processing` 超过处理阈值且心跳没有更新：先抢占恢复；
- 已有 provider 任务编号的任务不盲目重复调用，优先按 provider 状态或已有结果恢复；
- 无法确认状态的任务达到最大恢复次数后失败退款。

### 幂等要求

- 退款前检查积分流水和 operation 状态；
- 清理文件失败不影响退款状态，但要保留 `cleanupPending` 和错误信息供下一轮重试；
- 生成记录 ID 使用 `requestId` 派生或先查后写，避免补救时产生重复记录；
- 正常删除生成记录时不能误删仍被 operation 引用的结果文件。

## 管理员价格输入校验

### 图片

继续使用统一成本配置：

```text
costs.image.perImage["1K"]
costs.image.perImage["2K"]
costs.image.perImage["4K"]
```

默认值保持：

```text
1K = 0.06
2K = 0.10
4K = 0.15
```

### 视频

继续使用：

```text
costs.video.perSecond["480p"]
costs.video.perSecond["720p"]
costs.video.perSecond["1080p"]
```

视频单位为元/秒，沿用当前配置，不在本次设计中凭空改价。

### 校验规则

前端输入框即时校验并显示错误；云端保存前再次校验，前端不能绕过：

- 不能为空；
- 必须是有限数字；
- 不得小于 0；
- 最多 4 位小数；
- 不得超过现有最大值限制；
- `currency` 只能是 `CNY`；
- 清晰度键必须属于已支持的固定集合。

不强制要求价格按清晰度递增，因为实际供应商计费规则不一定递增。保存成功后，输入框、清晰度下拉框、成本统计和后续调用统一读取同一份有效配置。

## 成本调用明细导出

在现有 `exportModelUsageStats` 导出文件中新增工作表“成本调用明细”。数据来源为 `model_usage_events`，按统计时间范围过滤，逐条导出以下字段：

| 导出列 | 内容 |
|---|---|
| 日期 | `dateKey` |
| 时间 | 调用发生时间 |
| 脱敏用户编号 | `userHash` |
| 请求编号 | `requestId` |
| 功能 | 生图、分析、人脸或视频 |
| Provider | 服务商名称 |
| 模型 | 模型名 |
| 图片清晰度 | 1K/2K/4K，无图片时为空 |
| 视频清晰度 | 480p/720p/1080p，无视频时为空 |
| 单价 | 当前事件记录的单价 |
| 数量/时长 | 图片数量或视频秒数 |
| 成本 | 实际或估算成本 |
| 成本来源 | `actual`、`estimated` 或 `unavailable` |
| HTTP 状态 | 上游状态码 |
| 是否成功 | 是/否 |
| 耗时 | 毫秒 |
| 成本配置版本 | 事件发生时使用的版本 |

导出限制：

- 继续使用管理员权限；
- 保持现有时间范围上限；
- 只导出脱敏用户编号；
- 不导出 API Key、Authorization、完整 OpenID、完整提示词、原始响应正文；
- 事件缺少成本时保留“未计价”标记，不擅自补当前价格覆盖历史事实。

## 错误处理

### 用户侧

- 提交成功：显示“任务已提交，后台生成中”，允许离开页面；
- 排队中：显示“排队中”；
- 生成中：显示阶段和已等待时间；
- 成功：自动展示图片并写入本地记录；
- 失败：显示简短原因、请求编号和退款提示；
- 网络中断：保留任务编号，恢复网络或重新进入页面后继续查询；
- 禁止在状态不确定时直接重新提交新编号，页面先提示已有任务。

### 服务端

- 入口校验失败不创建收费任务；
- 入队和积分预留必须幂等；
- worker 失败先记录 operation，再退款；
- 退款失败保留 `refunding` 状态，下一轮继续；
- 记录写入失败不立即删除已上传结果，先走补救；
- 所有日志只记录脱敏 ID 和必要摘要。

### 性能验收

- 提交接口不再等待凌云完整响应；
- 素材下载阶段不再按主图、mask、参考图全部串行等待；

- 以现有约 59 秒上游耗时为基线，只比较外围耗时和用户可感知等待，不承诺改变模型本身计算速度。
