# 管理员视频模型星炬参数自动显示设计

## 1. 目标

在管理员页面的“视频模型”配置区中，选择或输入“星炬”后，自动补齐并显示星炬视频模型的已知参数，减少页面出现空白配置的情况。

本次只改管理员配置体验，不修改用户端视频制作流程，也不改变生图主模型、备用模型和腾讯版流程。

## 2. 页面行为

当视频模型服务商被识别为 `xingju` 或“星炬”时：

- 使用的模型自动补为 `grok-imagine-video-1.5`（仅当当前为空时补齐）；
- 创建路径自动补为 `/v1/videos/generations`（仅当当前为空时补齐）；
- 查询路径自动补为 `/v1/videos/{taskId}`（仅当当前为空时补齐）；
- 清晰度自动补为 `720p`（仅当当前为空时补齐）；
- 超时自动补为 `90000` 毫秒（仅当当前为空或无效时补齐）；
- 宽高比继续允许为空，不强行写入；
- 接口地址优先使用云端当前有效视频配置；云端也没有时保持空值并提示需要填写，不复用生图接口地址；
- API Key 通过管理员专用配置接口读取并显示完整内容，输入框允许管理员修改。

如果管理员从星炬切换到其他服务商，只补齐其他服务商已有的当前配置默认值，不把星炬参数强行带过去。手动修改过的非空参数不被自动覆盖。

## 3. API Key 显示规则

继续复用管理员权限校验，在现有管理员完整 Key 读取接口中增加视频 Key 返回值：

```js
{
  image: { apiKey: "..." },
  imageBackup: { apiKey: "..." },
  video: { apiKey: "..." }
}
```

规则：

- 只有管理员上下文可以读取；
- 只在管理员页面的表单中显示；
- 普通用户页面、日志、配置审计、错误提示、发布清单不出现完整 Key；
- 保存时沿用现有“空值继续使用云端旧 Key”的逻辑；
- 不在代码中写入真实 Key，不提交真实 Key，不在测试输出中打印真实 Key；
- 页面提示明确说明这是云端当前实际生效的完整 Key。

## 4. 前端改动边界

涉及：

- `pages/admin/admin.js`：星炬参数补齐、视频 Key 合并、表单状态更新；
- `pages/admin/admin.wxml`：视频 API Key 改为管理员可见的完整内容提示，补充星炬参数说明；
- `pages/admin/admin.wxss`：必要的 Key 状态和参数提示样式；
- `services/cloud.js`：管理员完整 Key 结果增加视频字段的兼容解析。

不改：

- 用户端视频上传、创建、轮询逻辑；
- 生图主模型和备用模型；
- 腾讯人脸融合配置；
- 云函数视频接口协议。

## 5. 后端改动边界

涉及：

- `cloudfunctions/api/index.js`：管理员完整 Key 接口返回视频 Key；
- 继续使用现有环境变量 `AI_VIDEO_API_KEY` / `AI_VIDEO_KEY`；
- 不新增密钥存储位置，不把 Key 写入 `admin_runtime_config`；
- 不调整视频请求的 provider、model、endpoint 路由规则。

## 6. 失败处理

- 管理员完整 Key 接口失败：视频参数仍正常显示，Key 输入框显示“完整 Key 读取失败”，不阻塞其他配置；
- 视频云端配置为空：页面显示“未配置接口地址”，不偷偷复用星炬生图地址；
- 当前模型已经填写：不自动覆盖；
- 当前路径、清晰度或超时已经填写：不自动覆盖，只有空值或明显无效值才补齐；
- 保存失败：保留管理员当前输入，沿用现有错误提示。

## 7. 测试验收

增加或更新专项检查：

1. 空视频配置识别为星炬后，模型、路径、清晰度、超时自动补齐；
2. 已填写的模型、路径、清晰度和超时不会被覆盖；
3. 云端视频接口地址能显示到管理员表单；
4. 管理员完整 Key 接口返回视频字段；
5. 视频 Key 会进入管理员表单，但不会进入配置摘要、审计日志和测试输出；
6. 保存视频配置仍发送 `provider=xingju` 和补齐后的参数；
7. 其他模型配置不受影响；
8. `node scripts/validate.js` 通过；
9. 正式打包前重新执行管理员配置和视频模型相关 smoke test。

## 8. 发布

这是管理员配置功能增强，代码测试通过后按项目规则升级版本、重新打包；如果云函数接口有改动，则部署 `api` 并做线上只读核验。
