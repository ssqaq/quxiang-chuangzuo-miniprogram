# 全部图片任务保持使用凌云设计

## 目标

正式环境中的图片生成和图片编辑统一使用凌云 `gpt-image-2`。星炬
`jw-gpt-image-2` 不再进入正式请求顺序，但保留协议适配代码，方便以后需要时恢复。
现有凌云视频链路保持不变。

## 当前问题

当前代码默认把星炬设为图片主模型，并按“星炬第 1 次、星炬第 2 次、凌云第
1 次”的顺序请求。管理员配置迁移也会把旧的凌云主配置改成星炬主配置，因此
只改一次线上数据库配置并不可靠。

## 方案

1. 默认图片主配置改为凌云：
   - provider：`lingyun`
   - base URL：`https://api.lingyunapi.xyz/v1`
   - model：`gpt-image-2`
   - mode：`edits`
2. 图片重试只使用当前凌云主配置，不再把星炬插入正式请求顺序。
3. 管理员旧配置迁移把现有凌云备用 Key 安全迁回凌云主配置；星炬 Key 不写入
   凌云配置，也不在日志中输出。
4. 管理后台默认值、状态文案、成本归属和文档统一显示凌云为图片主模型。
5. 星炬 JSON + Base64 适配代码和独立协议测试保留，但不参与正式调用。

## 数据流

小程序上传主图、mask 和参考图后，云函数读取凌云主配置，按现有
`lingyun-json` 格式发送 Base64 Data URL。临时错误时仍按现有规则重试凌云；
请求参数、图片格式或大小错误直接返回，不重复消耗上游额度。

## 兼容和回滚

- 已保存的星炬主配置会迁移为凌云主配置，优先复用原有凌云备用 Key。
- 如果没有凌云 Key，配置检查明确提示未配置，不会回退星炬。
- 星炬适配代码不删除。以后恢复时只需重新启用 provider 路由和管理员配置。

## 验证

1. 单元测试确认默认 provider、model、URL 和成本归属为凌云。
2. 主备编排测试确认所有实际尝试均为凌云，不出现星炬。
3. 管理员迁移测试确认凌云 Key 被保留，星炬 Key 不串用。
4. 完整校验、正式打包和云函数部署通过。
5. 使用真实主图、mask 和参考图跑一遍线上链路，确认记录中的 provider 为
   `lingyun`，且图片结果、尺寸恢复和圈外像素保护正常。
