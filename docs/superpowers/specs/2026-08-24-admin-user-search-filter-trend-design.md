# 管理页用户搜索、日期筛选与新增趋势设计

## 目标

在现有用户统计 D 方案内增加三个管理功能：

1. 按昵称或匿名编号搜索已完善资料的用户。
2. 按注册日期查看全部、今天、近 7 天或近 30 天的用户。
3. 用最近 7 天柱状图展示每天新增的已完善资料用户数。

搜索和日期筛选必须基于完整用户资料数据，不能只过滤当前页面已经加载的 20 条。

## 页面结构

1. 保留 D 方案顶部标题、刷新、导出、总人数、女性圆环和男女卡片。
2. 在说明文字下方增加搜索框，支持输入昵称或匿名编号，并提供搜索、清空操作。
3. 在搜索框下方增加四个日期选项：全部、今天、近 7 天、近 30 天。
4. 在男女卡片下方增加“最近 7 天新增用户”柱状图。
5. 用户明细继续分页，每次加载 20 条。

## 数据规则

- 只统计同时填写了昵称和性别的已完善资料用户。
- 搜索忽略昵称英文大小写，昵称使用包含匹配；匿名编号使用包含匹配。
- 日期按 `Asia/Shanghai` 判断今天和最近天数。
- 顶部总人数、男女数量、男女比例和明细都跟随当前搜索及日期条件变化。
- 新增趋势固定展示最近 7 天完整用户新增数量，不受当前搜索和日期筛选影响，避免趋势含义反复改变。
- 趋势柱高按最近 7 天最大值换算；全部为 0 时仍显示日期和 0 人。

## 接口与导出

- `getAdminUserStats` 接收 `search` 和 `dateRange`，返回筛选后的统计、分页明细和最近 7 天趋势。
- `exportAdminUserStats` 接收相同条件，只导出当前搜索和日期筛选后的用户。
- 云函数继续只返回匿名编号，不返回原始 OpenID。
- 搜索词最长 32 个字符；日期范围只接受 `all`、`today`、`7d`、`30d`。

## 状态处理

- 切换日期后自动从第一页重新读取。
- 点击搜索后从第一页重新读取；空搜索等同显示全部昵称。
- 点击清空后移除搜索词并重新读取当前日期范围。
- 筛选后没有用户时显示“没有符合条件的用户”。
- 请求失败时保留页面原有数据，并显示失败原因。

## 验证标准

- 搜索昵称和匿名编号都能得到正确结果。
- 今天、近 7 天、近 30 天的边界日期计算正确。
- 筛选后的总人数、男女统计和分页数量一致。
- 最近 7 天趋势按上海日期正确分组。
- 导出文件只包含当前筛选结果。
- 原有刷新、加载更多、隐私隐藏和 D 方案排版保持可用。
- 专项测试和完整静态检查通过。
