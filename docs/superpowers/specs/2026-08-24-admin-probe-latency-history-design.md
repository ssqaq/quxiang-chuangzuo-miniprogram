# 管理页探针耗时与历史设计

## 目标

在已有自动贴脸探针结果的基础上补两项能力：

1. 管理页显示本次探针接口耗时。
2. 管理员主动点击“立即检查线上部署”时，把探针结果保存为历史，并在管理页查看最近记录。

自动贴脸失败时携带的探针快照继续保存在 `auto_face_failure_logs` 中，不与管理员主动检查历史混合。

## 现状

- 云函数 `probeAutoFace` 当前只返回脱敏运行状态，不记录数据库历史。
- 管理页已有当前探针卡片，但 `durationMs` 没有由客户端测量，通常为 0。
- 自动贴脸失败统计已经从失败记录中汇总探针状态、版本和视觉配置状态。
- 管理员权限由云函数 `isAdminContext` 统一校验。

## 方案

### 数据集合

新增集合 `auto_face_probe_logs`，每条记录保存：

- `status`：`ok` 或 `failed`
- `buildVersion`
- `buildMarker`
- `nodeVersion`
- `cloudEnvConfigured`
- `visionConfigured`
- `provider`
- `model`
- `durationMs`
- `errorCode`
- `checkedAt`
- `createdAt`

不保存 API Key、图片地址、提示词、完整 OPENID 或错误堆栈。

历史保留最近 30 天。读取时最多返回 20 条；云函数读取时懒清理过期记录，每次最多删除 100 条。

### 云函数接口

保留现有 `probeAutoFace` 返回格式，并在服务端测量探针处理耗时：

```text
durationMs = probeAutoFace 函数从进入到返回前的耗时
```

只有管理员主动调用时才写入历史。为避免普通调用绕过权限，`probeAutoFace` 接收并校验云函数上下文。

新增 `getAutoFaceProbeHistory`：

- 仅管理员可调用；
- 默认查询最近 30 天；
- 返回最近 20 条；
- 数据库不可用时返回 `unavailable` 和中文提示，不影响当前探针结果展示。

### 管理页

自动贴脸探针卡片增加：

- `接口耗时`

新增“探针历史”区域：

- 时间
- 检查结果
- 耗时
- 云函数版本
- 视觉配置状态
- Provider / Model
- 错误码（失败时显示）

点击“立即检查线上部署”时同时刷新：

- 当前部署信息
- 当前探针结果
- 探针历史

页面打开时加载一次历史；历史读取失败只显示提示，不阻断管理员配置和部署检查。

## 数据流

1. 管理员点击检查。
2. 小程序调用部署检查和探针接口。
3. 云函数校验管理员权限，测量探针耗时，写入脱敏历史。
4. 云函数返回当前探针结果。
5. 小程序重新读取最近探针历史并显示。

## 测试

- 探针服务端耗时必须是非负整数，并限制最大值。
- 探针历史必须脱敏，不能出现 Key、图片地址、OPENID、堆栈。
- 非管理员读取历史必须返回 `ADMIN_FORBIDDEN`。
- 管理员能读取历史，按时间倒序，最多 20 条。
- 过期历史能被懒清理。
- 管理页能显示当前探针耗时和历史条目。
- 原有自动贴脸失败统计、探针脱敏和兼容测试继续通过。
