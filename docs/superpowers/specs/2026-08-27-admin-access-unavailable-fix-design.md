# 管理员状态调用失败误报修复设计

## 问题

管理员账号进入控制台时出现“当前微信账号不在管理员白名单中”，但线上核验已经确认：

- 当前微信登录态有效；
- 云函数环境变量 `ADMIN_OPENIDS` 已配置；
- 当前账号的原始 OpenID 和不可逆识别码都能匹配白名单；
- GitHub 最新版本为 `0.48.3`，线上 `api` 云函数仍为 `0.48.2`；
- `services/cloud.js` 在静默调用失败时返回 `unavailable: true` 和 `isAdmin: false`；
- 管理员页没有先判断 `unavailable`，直接把调用失败当成白名单拒绝。

因此截图里的“无权访问”是前端状态误判，不是管理员授权被删除。

## 目标

1. 只有云端明确识别到用户且确认不在白名单时，才显示“无权访问”。
2. 云函数调用失败、超时或暂时不可用时，留在管理员页并允许重试。
3. 云端无法取得微信身份时，显示身份识别失败并允许重试，不伪装成白名单拒绝。
4. 不增加本地管理员后门，不使用缓存绕过云端授权。
5. 发布后把最新版 `api` 云函数部署到 CloudBase，并核对线上版本。

## 状态判断顺序

管理员页收到 `getAdminStatus` 结果后严格按以下顺序处理：

1. **服务不可用**：`status.unavailable === true`
   - `isAdmin` 保持 `false`；
   - `canRetry` 设为 `true`；
   - 显示“管理员服务暂时不可用，请稍后重试”；
   - 不弹“无权访问”，不跳回工作台。
2. **授权成功**：`status.isAdmin === true`
   - 正常加载管理员配置和统计模块。
3. **身份无法识别**：`status.isAdmin === false` 且没有 `identityHash`
   - `canRetry` 设为 `true`；
   - 显示“暂时无法识别微信身份，请重试”；
   - 不弹“无权访问”，不跳回工作台。
4. **确认无权限**：`status.isAdmin === false` 且存在 `identityHash`
   - 显示识别码和白名单配置提示；
   - 弹出“无权访问”；
   - 用户确认后返回工作台。

页面内容仍然只在 `isAdmin === true` 时显示，服务异常不会放宽权限。

## 修改范围

- `pages/admin/admin.js`
  - 调整 `loadAdminPage` 的管理员状态分支顺序。
- `scripts/admin-loading-smoke.js`
  - 增加服务不可用和身份无法识别的回归断言。
- 如现有测试结构不适合隔离授权分支，可新增一个小型管理员授权 smoke；不修改授权算法和白名单格式。

## 验证

至少覆盖以下场景：

1. `unavailable: true`：显示可重试状态，不弹无权访问，不跳转。
2. 无识别码的非管理员结果：显示身份识别失败，不弹无权访问。
3. 有识别码的非管理员结果：维持原白名单拒绝行为。
4. `isAdmin: true`：继续加载管理员配置。
5. 现有管理员加载、布局、配置和静态检查全部通过。

## 发布与部署

1. 从最新 `origin/main` 的干净分支实施修改。
2. 自动分配下一个补丁版本并生成正式 ZIP。
3. 只提交本任务文件和自动版本文件，推送 GitHub。
4. 部署新版 `cloudfunctions/api`，不能只生成发布包。
5. 只读核验线上版本、构建标记、函数状态和超时配置。
6. 使用当前微信登录态重新进入管理员页，确认不再误报。

## 不做的事

- 不删除或放宽 `ADMIN_OPENIDS` 校验。
- 不把 OpenID 写入前端、源码、日志或发布包。
- 不使用本地缓存直接放行管理员页面。
- 不顺带修改管理员页面布局或统计功能。
