# 管理员模型配置连接操作设计

## 目标

在管理员页的四个模型配置区顶部增加两个可直接使用的操作：

- “测试连接”：检查当前填写的服务商、接口地址、密钥和模型是否可用。
- “获取模型”：读取当前接口返回的模型列表，供管理员选择并填入“使用的模型”。

四个配置区统一支持：

1. 人脸识别模型。
2. 图片分析模型。
3. 生图模型。
4. 视频模型。

当前页面已有的保存、刷新、全局模型探测和旧配置兼容逻辑继续保留。

## 页面交互

### 操作按钮

- 每个模型配置区的标题区域增加一行操作按钮。
- 两个按钮右上横向排列，尺寸小于“保存全部配置”，不挤压下面的表单。
- 请求进行中时按钮禁用并显示“测试中”或“读取中”，避免重复点击。
- 按钮操作使用页面当前表单值，不要求先点击“保存全部配置”。

### 测试连接

点击后按当前配置执行检查：

1. 检查服务商、接口地址、密钥和模型字段是否完整。
2. 请求接口的模型列表地址，确认服务可以访问。
3. 检查当前填写的模型是否出现在返回列表中。
4. 成功时提示“连接成功，模型可用”。
5. 地址不可访问、密钥错误、接口不支持模型列表或模型不存在时，显示具体原因。

测试只读取接口，不保存配置，不改变表单内容。

### 获取模型

点击后按当前服务商、接口地址和密钥请求模型列表：

1. 成功时打开可滚动的模型选择面板。
2. 面板显示模型名称，必要时显示接口返回的模型描述。
3. 点击某个模型后关闭面板，并把模型名称填入当前配置区的“使用的模型”。
4. 取消或关闭面板时不修改模型输入框。
5. 获取失败时保留原输入内容，并显示可读的失败原因。
6. 选中的模型只写入当前页面表单，仍需手动保存才会生效。

## 后端与数据流

- 新增一个管理员专用的“读取模型列表”能力，复用现有接口地址拼接、密钥认证和模型响应解析逻辑。
- 请求参数包含模型类型以及当前页面提交的临时配置；后端不把临时配置写入数据库。
- 支持现有兼容接口常见响应格式：
  - `data: [{ id }]`
  - `models: [{ id }]`
  - `result.data: [{ id }]`
  - 列表元素为字符串的情况。
- 保留现有 `probeModels` 的四套模型探测逻辑；新操作可以复用底层的 URL、请求头和模型 ID 解析函数，但不改变全局探测结果结构。
- 不在日志中记录完整 API Key，只记录模型类型、接口地址的脱敏信息、结果状态和耗时。

## 错误处理

- 未填写接口地址时，不发起网络请求，直接提示“请先填写接口地址”。
- 未填写密钥时，直接提示“请先填写接口密钥”。
- 接口返回 401/403 时提示密钥或权限错误。
- 接口返回 404 或不支持模型列表时提示接口地址应填写兼容接口根地址。
- 返回列表为空时提示“接口没有返回可用模型”。
- 当前模型不在列表中时，测试结果明确标记为“接口可访问，但当前模型不存在”。
- 所有请求设置超时，并在结束后恢复按钮可点击状态。

## 验收条件

1. 四个模型配置区都显示“测试连接”和“获取模型”。
2. 两个按钮上下位置整齐，不覆盖输入框和保存按钮。
3. “获取模型”能从当前接口读取列表并弹出选择面板。
4. 选择模型后只更新对应区域的模型输入框。
5. “测试连接”同时验证接口可访问和当前模型存在。
6. 未保存的临时地址、密钥和模型也能被测试和读取模型使用。
7. 失败时有明确中文提示，按钮不会永久处于加载状态。
8. 原有保存配置、全局探测和管理员页面功能通过回归检查。
