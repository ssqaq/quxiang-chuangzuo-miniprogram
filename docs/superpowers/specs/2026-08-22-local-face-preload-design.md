# 本地人脸识别预下载与分阶段初始化设计

## 1. 目标

解决“红圈自动贴脸”在模拟器和真机上长时间停留在“识别中”后超时的问题，并保留识别失败时回退到手动圈选的能力。

验收标准：

1. 小程序启动后后台开始下载模型和 WASM，不阻塞启动页和首页显示。
2. 进入主图页面后，复用同一份资源 Promise 初始化 MediaPipe，不重复下载、不重复启动。
3. 点击“红圈自动贴脸”时，直接复用已经完成的运行时；如果仍在初始化，只等待同一个初始化 Promise。
4. 控制台能看到下载、缓存、Canvas、MediaPipe、识别开始和识别完成等阶段日志。
5. 任一阶段失败都能给出具体阶段错误，并继续允许用户手动圈选。
6. 资源缓存继续放在 `wx.env.USER_DATA_PATH/circle-face-runtime`，识别仍在本地完成，不调用 AI 分析 API Key。

## 2. 当前问题和证据

- 当前 `utils/local-face.js` 把资源读取、云端下载、Canvas 创建和 MediaPipe 初始化全部放在一次 `createRuntime()` 中。
- 页面只有点击自动贴脸时才触发 `getRuntime()`，启动和页面进入阶段没有预热。
- 当前只有一个总超时，日志不能判断卡在缓存、下载、Canvas 还是 MediaPipe。
- 用户已经在模拟器和真机上复现“模型初始化超时”。

## 3. 方案选择

### 方案 A：启动时完整初始化 MediaPipe

启动时下载资源并创建 MediaPipe。优点是点击后最快；缺点是会抢占启动阶段内存和 CPU，可能拖慢首页，也无法区分资源下载问题和运行时初始化问题。

### 方案 B：只在点击时初始化

保持现状，只增加日志。改动小，但首次点击仍然要承担所有下载和初始化耗时，不能解决用户等待时卡住的体验。

### 方案 C：后台预下载 + 页面内初始化 + 点击复用（采用）

启动后只后台下载并缓存资源；进入主图页面时初始化 MediaPipe；点击时复用已有 Promise。这样不阻塞首页，又能提前消化下载时间，并能把故障拆成资源阶段、Canvas 阶段和 MediaPipe 阶段。

## 4. 组件和数据流

### `utils/local-face.js`

- 增加 `preloadFaceAssets()`：只负责读取缓存或下载模型/WASM。
- 增加 `initializeFaceRuntime()`：复用资源 Promise，创建 OffscreenCanvas 和 FaceLandmarker。
- 保留 `detectFaceCircles()`：复用运行时，执行本地图像识别。
- 增加 `getStatus()` 和 `subscribeStatus(listener)`：提供当前阶段和错误信息。
- 所有资源、Canvas、MediaPipe 和识别步骤统一记录 `[local-face]` 阶段日志。
- 继续保留并发 Promise，避免重复下载或重复启动。

### `app.js`

CloudBase 初始化成功后，用 `setTimeout(..., 0)` 后台调用 `preloadFaceAssets()`。失败只记录日志，不阻塞小程序。

### `pages/index/index.js`

- 页面加载时订阅本地人脸状态。
- 页面加载后后台调用 `initializeFaceRuntime()`，不阻塞页面渲染。
- 自动贴脸继续调用 `detectFaceCircles()`，失败时显示阶段化错误并回退手动圈选。
- 页面卸载时取消状态订阅并关闭运行时。

### `pages/index/index.wxml`

在自动贴脸按钮附近显示简短的本地模型状态、百分比和进度条，例如“正在下载模型 40%”“正在初始化本地识别 92%”“本地模型已就绪 100%”。详细信息仍放在控制台日志，避免页面变得拥挤。

## 5. 错误处理

- 缓存不存在：进入下载阶段。
- 缓存读取超时：判定为异常缓存，清理后重新下载；下载临时文件优先复制到 `USER_DATA_PATH`，再从稳定缓存路径读取。
- 临时 URL 或下载失败：记录资源名称和具体错误。
- 缓存写入失败：不影响本次识别，继续使用临时文件。
- Canvas/WebGL 不可用：明确提示设备不支持本地识别，保留手动圈选。
- MediaPipe 初始化超时：只结束当前等待，不启动第二套运行时；下次点击允许重试。
- 识别超时或没有检测到人脸：提示手动圈选，不影响其他功能。

## 6. 验证计划

1. Node 静态语法检查和工程 `validate.js`。
2. `compat-smoke.js` 与本地人脸模块接口级检查。
3. 检查开发者工具模拟器日志，确认阶段日志顺序和错误位置。
4. 真机验证首次启动后台下载、再次进入命中缓存、点击自动贴脸成功或明确回退。
5. 升级补丁版本并正式打包，记录产物路径。
6. 重新部署 `cloudfunctions/api`，确认远端包包含 `lib/retry.js`。

## 7. 风险和回滚

- 低版本基础库可能不支持 OffscreenCanvas 或 WebGL：保留当前手动圈选回退。
- 页面卸载时不能强行取消底层 Promise：继续复用 Promise，避免重复初始化。
- 本次只改本地人脸启动链路、页面状态、云函数部署包和版本号，不改 AI 分析接口协议。
- 如新链路在真机仍不兼容，可临时关闭页面预热，只保留资源预下载和手动圈选。
