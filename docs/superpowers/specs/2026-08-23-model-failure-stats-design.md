# 模型调用失败统计设计

## 目标

在管理员“模型用量统计”中增加模型调用失败分析，帮助快速判断哪个模型、Provider 或错误类型最不稳定。

本次只增加后台统计和 Excel 导出，不改变用户端生图、人脸识别、视频功能的调用流程。

## 失败事件记录

继续使用 `model_usage_events` 集合，在失败事件中补充：

- `errorCode`：程序错误码或上游错误码；
- `errorMessage`：脱敏后的简短错误说明；
- `errorStatus`：HTTP 状态码；
- `retryable`：是否允许重试；
- `attempt`：实际尝试次数；
- `failedAt`：失败发生时间。

错误信息统一做长度限制和敏感内容清理，不保存 API Key、真实 OpenID、图片地址、请求头和完整上游响应。

旧事件没有失败字段时，归入“未提供错误原因”，不影响原有调用次数和成本统计。

## 聚合统计

服务端在现有 `aggregateModelUsageEvents` 基础上增加：

- `failureCount`：失败总次数；
- `failureRate`：失败次数 ÷ 总调用次数；
- `failureReasons`：按错误原因聚合并按次数从高到低排序；
- `topFailureReasons`：只返回前 5 个失败原因；
- `failedModels`：按 Provider、模型和模型类型统计失败次数；
- 每个失败原因包含次数、占比、最近一次发生时间。

失败原因优先使用 `errorCode`，没有错误码时使用清理后的 `errorMessage`，都没有时使用“未提供错误原因”。

统计时间范围沿用现有口径：

- 今日；
- 最近 7 天；
- 最近 30 天；
- 最近 12 个月按月汇总。

## 管理员页面

在现有“模型用量统计”区域增加“失败情况”模块，展示：

1. 今日失败次数和失败率；
2. 最近 7 天失败次数；
3. 最近 30 天失败次数；
4. 失败次数最多的模型；
5. 失败原因前 5 名；
6. 失败最多的 Provider / 模型。

页面默认只显示前 5 个原因，避免失败日志过多导致页面过长。

## Excel 导出

在现有模型用量 Excel 中增加“失败明细”工作表，导出当前统计范围内的完整失败记录：

- 日期和时间；
- 模型类型；
- Provider；
- 模型名称；
- 错误代码；
- 错误说明；
- HTTP 状态码；
- 是否可重试；
- 尝试次数；
- 请求耗时。

导出内容只使用脱敏后的字段，不包含真实 OpenID、API Key、图片 fileID、请求头和完整响应体。

## 兼容和错误处理

- 统计读取失败不影响模型调用；
- 旧事件没有失败字段时正常显示；
- 成功事件不进入失败原因统计；
- 同一请求重试失败只保留一次最终失败事件，不把内部重试次数误算成多次调用；
- 统计接口继续只允许管理员访问；
- 没有失败记录时展示空状态，不报错。

## 验证

新增专项测试覆盖：

- 失败事件字段规范化和脱敏；
- 失败次数、失败率和 Top 5 排序；
- 按 Provider 和模型分组；
- 旧事件缺失错误字段的兼容；
- Excel“失败明细”工作表；
- 非管理员无法读取失败统计；
- 成功事件不会被统计为失败。
