# 备用模型独立检测按钮设计

## 目标

在管理员页的“备用模型”配置卡片中，补齐三个与主模型对应的操作：

- 测试连接
- 获取模型
- 检查图片编辑配置

三个操作只针对 `imageBackup` 配置，结果也只显示在备用模型卡片中，不能覆盖主模型的检测结果。

## 交互设计

备用模型的三个按钮放在备用模型标题下方、备用模型参数表格上方，与主模型按钮保持同样的视觉样式。

- “测试连接”：调用现有模型探测接口，传入备用模型的 Provider、地址、模型和 API Key。
- “获取模型”：调用现有模型列表接口，传入备用模型配置；选择列表项后只写回 `form.imageBackup.model`。
- “检查图片编辑配置”：调用现有只读配置检查接口，传入备用模型配置；不调用生图、不扣额度。

备用模型使用独立的加载状态和检查结果：

- `imageBackupEditCapabilityLoading`
- `imageBackupEditCapabilityProbe`

模型按钮沿用现有公共加载状态，但额外记录操作目标，避免主备按钮同时显示“处理中”。

## 后台与数据流

后台不新增接口。现有 `probeModels`、`listModels`、`probeImageEditCapability` 都继续使用 `modelType: "image"`，前端把备用模型配置作为临时配置传入，后台不会保存临时配置。

模型列表弹窗增加目标配置标记：

- 主模型：`image`
- 备用模型：`imageBackup`

这样弹窗仍按“生图模型”展示，但选择结果只更新对应配置。

## 错误处理

- 请求失败沿用现有管理员页错误弹窗和诊断日志。
- 主模型检测结果和备用模型检测结果互不覆盖。
- 备用模型检查失败时保留上一次主模型检查结果，反之亦然。
- 所有结果中的 API Key 只显示“已配置/未配置”，不显示密钥内容。

## 验收

1. 备用模型卡片出现三个按钮。
2. 备用“测试连接”请求使用 `imageBackup` 配置。
3. 备用“获取模型”选择后只改变 `form.imageBackup.model`。
4. 备用“检查图片编辑配置”结果显示在备用卡片，且不改变主模型结果。
5. 主模型三个按钮原行为不变。
6. 主备按钮加载状态互不误显示。
7. 静态检查和管理员页专项测试通过。
