# 星炬 JSON + Base64 图片编辑适配设计

## 目标

让星炬 `jw-wy-gpt-image-2` 稳定接入现有图片编辑主备流程，并继续保证普通版红圈外像素不变、腾讯版第一阶段脸部保护区不被图片模型重画。

## 请求协议

- 星炬 `jw-wy-gpt-image-2` 固定走 `application/json`。
- 主图和参考图放入 `images[].image_url`，内容为 Data URL。
- mask 放入 `mask.image_url`，内容为 Data URL。
- 星炬固定发送 `response_format: "b64_json"` 和 `output_format: "png"`。
- 凌云 `gpt-image-2` 保留现有 JSON Data URL 协议和可配置返回格式。
- 其他兼容服务继续使用现有 multipart 协议，不扩大改动范围。
- 日志分别标记为 `xingju-json`、`lingyun-json` 或 `multipart`，方便定位上游问题。

## 尺寸归一化

- 图片模型结果先解码为 RGBA。
- 如果模型结果尺寸与原图一致，直接进入现有像素合成。
- 如果尺寸不同，使用双线性缩放直接映射到原图宽高。
- 缩放后继续使用原图坐标系中的 ellipse 或人脸矩形 mask。
- 普通版和腾讯版第一阶段共用同一尺寸归一化函数。
- 结果中记录缩放前尺寸、目标尺寸、是否缩放和缩放策略。

## 像素保护

- 普通版仍只使用模型结果覆盖红圈内部，红圈外从原图逐像素复制。
- 腾讯版第一阶段仍只使用模型结果覆盖脸部保护区以外，脸部区域从原图逐像素复制。
- 最终输出继续使用无损 PNG 编码并做回环校验。
- 圈外或保护区外的 exact mismatch 必须为 0，否则任务失败。

## 主备切换

- 星炬为主模型，最多调用两次。
- 星炬临时错误或鉴权错误可按现有规则切换凌云。
- 请求格式错误、模型配置错误和像素保护错误不做无意义重试。
- 每次调用继续使用独立幂等键，避免重复计费或重复任务。

## 验证

- 星炬请求必须是 JSON，不能出现 multipart。
- 多图顺序必须是主图在前、参考图在后，mask 单独发送。
- 星炬必须固定请求 Base64 PNG 返回。
- 使用 `1024x1536` 模型结果对齐 `896x1195` 原图，最终尺寸必须为 `896x1195`。
- 普通版红圈外 exact mismatch 必须为 0。
- 腾讯版第一阶段脸部保护区 exact mismatch 必须为 0。
- 凌云 JSON 行为和星炬失败后切换凌云的行为必须继续通过测试。
