# 管理员页运行监控「深海指挥台」设计

## 1. 目标

把管理员页现有“运行监控”区域改成用户已选定的 **01 号「深海指挥台」** 手机端布局。重点是让系统状态、异常日志、部署和探针信息更容易扫读，同时完整保留现有按钮、筛选、详情和检查能力。

这次只改运行监控局部，不重做管理员页，不新增模型用量功能。

## 2. 修改范围

只优化以下六个模块及其内部现有功能：

1. 运行监控总开关
2. 系统运行概览
3. 用户端日志
4. 部署与探针
5. 探针历史
6. 部署检查日志

明确不修改：

- 模型用量、Token、人民币金额、今日成本
- 模型调用成功/失败统计及其月份、导出、明细功能
- 模型配置、用户统计、积分、其他管理员模块
- 其他业务页面和云函数接口

## 3. 页面结构

### 3.1 运行监控总开关

- 保持白色独立卡片。
- 左侧显示“运行监控”和简短状态摘要。
- 右侧保留“展开/收起”按钮与箭头。
- 继续使用现有 `monitorExpanded`、`toggleMonitor` 和本地布局记忆，不改变开关行为。

### 3.2 系统运行概览

- 使用深蓝色主卡片，作为运行监控的视觉中心。
- 上方显示“系统运行概览”。
- 主状态继续显示 `dashboardStatus.title`，例如“全部正常”“配置未完成”“探针异常”。
- 下方显示三项可点击数据：
  - 错误日志：`diagnosticLogs.summary.errorCount`
  - 部署记录：`logs.length`
  - 探针历史：`autoFaceProbeHistory.history.length`
- 三项分别跳到并展开对应区域。
- 删除概览卡里的“今日成本”和模型用量跳转。
- `dashboardStatus` 只根据部署配置和探针状态判断，不再根据模型调用失败次数改变标题，避免运行监控继续依赖模型用量数据。

### 3.3 用户端日志

- 使用白色卡片，标题前增加状态点：有错误时为红色，没有错误时为绿色。
- 标题下显示保留时间、日志总数和错误数的简短摘要。
- 右侧保留读取状态、刷新、展开/收起。
- 展开后完整保留：
  - 全部、错误、提醒、正常、用户数量
  - 时间范围筛选
  - 严重程度筛选
  - 业务类型筛选
  - 用户筛选
  - 分类汇总
  - 日志列表
  - 复制日志
  - 查看/收起详情
  - 加载更多
- 不改 `refreshDiagnosticLogs`、各筛选事件、复制和详情事件。

### 3.4 部署与探针

- 使用白色分组卡片。
- 标题前保留状态点：所有部署项就绪时为绿色，否则为红色。
- 标题下显示“运行正常/需要处理”和探针历史数量。
- 右侧保留展开/收起。
- 展开后继续保留：
  - 当前线上部署
  - 自动贴脸探针
  - 四套模型接口探测
  - 每个模型的单独探测
  - 原有状态、版本、耗时和修复提示
- 不改任何部署检查或模型探测接口。

### 3.5 探针历史

- 作为“部署与探针”里的独立子卡片。
- 标题右侧保留读取状态、刷新、展开/收起。
- 展开后保留加载态、失败提示、空状态和最多 20 条历史记录。
- 不改 `refreshAutoFaceProbeHistory` 和 `toggleDeploymentSection`。

### 3.6 部署检查日志

- 作为“部署与探针”里的独立子卡片。
- 标题右侧提供“立即检查”和“展开/收起”。
- “立即检查”直接复用现有 `checkDeployment`，检查中显示不可重复点击状态。
- 展开后保留读取状态、日志数量、加载态、失败提示、空状态和日志列表。
- 页面顶部原有“检查线上部署”入口不改，两个入口调用同一个现有检查逻辑。

## 4. 数据和事件

继续使用当前页面已经读取的数据：

- `dashboardStatus`
- `diagnosticLogs`
- `moduleStates`
- `deployment`
- `autoFaceProbe`
- `modelProbes`
- `autoFaceProbeHistory`
- `logs`
- `monitorExpanded`
- `monitorSections`
- `deploymentSections`

主要修改 `pages/admin/admin.wxml` 和 `pages/admin/admin.wxss`。`pages/admin/admin.js` 只做两类最小修改：

1. 让系统运行状态不再读取模型调用失败数量。
2. 如果探针历史概览需要点击定位，补一个复用现有展开状态和滚动能力的小事件。

不新增网络请求，不改变返回数据结构，不改云函数。

## 5. 视觉规则

- 页面底色、其他管理员卡片保持原样。
- 运行监控总开关：白底、浅蓝边、圆角卡片。
- 系统运行概览：深海蓝底、白色主标题、半透明数据格。
- 异常状态：红色小圆点和浅红强调，不整卡铺红。
- 正常状态：绿色小圆点。
- 操作按钮：浅蓝底、蓝色文字，保持“刷新”“展开/收起”“立即检查”的统一高度。
- 卡片间距、圆角和左右边界统一，避免不同模块宽度不齐。
- 不使用新图片、外部字体或远程资源。

## 6. 手机端规则

- 以微信小程序手机宽度为主，优先验证 375px 和 414px。
- 深蓝概览卡在窄屏改为上下布局，三项数据保持同一行；极窄时允许文字缩小，不出现横向滚动。
- 标题区按钮过多时优先压缩状态文字，不能把“刷新”和“展开/收起”挤出卡片。
- 用户端日志五项汇总在窄屏允许自动换行。
- 部署网格在窄屏保持现有单列规则。
- 长版本号、模型名、错误信息允许省略或换行，不能撑破页面。

## 7. 加载、失败和空状态

- 保留现有 skeleton、读取中、读取失败、无数据提示。
- 点击刷新或立即检查时继续使用现有 loading/disabled 状态，避免重复请求。
- 日志、部署或探针读取失败时，只在对应卡片显示提示，不影响其他模块展开和操作。
- 不增加新的全屏弹窗，不隐藏现有修复提示。

## 8. 验收标准

1. 运行监控总开关能正常展开、收起，并记住状态。
2. 深蓝概览不再出现今日成本、Token、人民币或模型用量入口。
3. 系统状态不再因为模型调用失败统计而变成“运行正常，有失败”。
4. 概览显示错误日志、部署记录、探针历史，点击后能定位到对应区域。
5. 用户端日志的刷新、四类筛选、用户筛选、复制、详情、加载更多全部可用。
6. 部署与探针的当前部署、自动贴脸探针、模型探测和单独探测全部保留。
7. 探针历史的刷新、展开/收起和列表全部可用。
8. 部署检查日志的立即检查、展开/收起和列表全部可用。
9. 模型调用失败统计本身不改样式、不改数据、不改事件。
10. 375px、414px 手机宽度无横向溢出，按钮不重叠。
11. 项目静态检查、管理员页响应式检查和正式打包通过。
