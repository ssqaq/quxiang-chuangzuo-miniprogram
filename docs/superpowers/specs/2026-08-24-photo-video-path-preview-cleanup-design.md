# 照片转动态视频路径、预览版本和云端清理设计

## 目标

本次只实现用户确认的三项：

1. 统一照片转动态视频的本地路径、云文件 ID 和结果字段；
2. 让预览二维码明确对应源码版本和 Git 提交；
3. 每天自动清理照片转动态视频产生且超过 3×24 小时的临时云文件。

普通 MP4 仍然是普通动态视频，不改称为 iPhone 原生 Live Photo。

## 1. 文件字段统一

新数据使用以下字段：

- `sourcePath`：当前设备上的源照片路径，用于预览和保存照片；
- `sourceFileID`：上传到云端的视频源照片；
- `resultPath`：当前设备上的结果视频路径，用于预览和保存视频；
- `resultFileID`：云端返回的结果视频；
- `displayURL`：仅用于页面显示的临时 URL，不作为保存依据。

读取旧记录时继续兼容 `path`、`tempFileURL`、`videoPath` 和 `videoFileID`，
并在进入处理流程时归一化。下载、预览和保存优先使用本地路径；本地路径失效
时，再使用对应 `fileID` 或临时 URL 重新取得本地文件。

## 2. 预览二维码版本绑定

保留现有按版本生成二维码的文件命名，并增加自己的元数据文件，至少记录：

- `appVersion`；
- 当前 Git 提交号；
- 生成时间；
- 二维码文件路径；
- 微信开发者工具返回的原始预览信息。

`refresh-preview.ps1` 生成版本二维码和 `latest` 快捷副本时，同时写入元数据。
校验脚本检查当前 `config.js` 版本对应的二维码和元数据是否存在、版本是否一致；
没有开发者工具或二维码未生成时，只明确报告“预览未生成”，不伪造已预览状态。

## 3. 云端三天自动清理

### 清理范围

只清理照片转动态视频登记过的临时文件：

- 视频任务上传的源照片；
- 视频服务返回并暂存在云端的结果视频。

不清理用户相册文件、正式制作记录、正式结果图，也不删除数据库中的业务记录。

### 登记方式

云端保存临时文件登记，包含：

- `fileID`；
- `kind`：`source` 或 `result`；
- `createdAt`；
- `cleanupAfter`；
- `status`；
- `attempts`；
- `lastError`。

同一个 `fileID` 去重，避免重复登记。

### 自动任务

云函数增加清理入口，由 CloudBase 每天触发一次。清理入口只处理
`cleanupAfter <= now - 3×24小时` 的登记项，每次限制最大数量。

删除成功或文件已经不存在时，删除登记；删除失败时保留登记并增加重试次数，
下一次自动任务继续处理。前端已有本地清理队列继续保留，作为用户侧兜底。

## 4. 测试和发布

增加或更新测试覆盖：

- 旧字段归一化和新字段优先级；
- 本地路径失效后的 `fileID` 回退；
- 预览元数据的版本和提交号匹配；
- 三天截止时间、重复登记、成功删除、文件不存在、失败重试；
- 清理入口不会触碰非照片转视频文件。

代码通过校验和 smoke 测试后，按项目规则升级补丁版本、生成正式 ZIP，
并执行 GitHub 同步。云函数自动清理需要部署后由 CloudBase 定时触发；
本地测试只验证清理逻辑，不把未部署状态写成已生效。
