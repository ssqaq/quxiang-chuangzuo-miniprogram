# GitHub 自动同步设计

## 目标

以后宝宝每次修改微信小程序源码、云函数、脚本或发布配置，完成检查后立即提交并推送到
`origin/main`，避免修改只停留在本机。

## 方案

1. `scripts/sync-to-github.ps1` 使用脚本自身位置定位仓库，不依赖固定盘符；
2. 同步前执行 `git pull --rebase --autostash`，降低远端有新提交时的冲突概率；
3. 有修改才提交，没有修改就安全退出，不制造空提交；
4. 提交完成后推送到 GitHub；拉取、提交或推送失败都以明确错误停止；
5. 使用仓库级 `AGENTS.md` 固化“修改完成后必须同步”的协作规则；
6. 配置 `.githooks/post-commit`，让其他本地提交也自动推送；
7. 取消 Windows 每 10 分钟同步任务，改为修改完成并验证后立即提交推送。
8. 同步前自动运行发布包检查，成功后生成仓库旁的版本 ZIP；
9. 根据已暂存文件生成提交标题、修改范围和文件摘要，避免所有提交都只有一个时间戳。

## 数据流

```text
宝宝修改代码
  -> 本地检查
  -> sync-to-github.ps1
  -> pull --rebase --autostash
  -> git add -A
  -> 有修改：生成发布包
  -> 生成提交摘要
  -> commit
  -> push origin main
  -> GitHub
```

普通手动提交则由 `post-commit` hook 直接推送；同步脚本提交时通过环境变量避免重复推送。

## 失败处理

- 远端拉取冲突：停止同步，保留现场，处理冲突后重新执行脚本；
- GitHub 推送失败：保留本地提交，网络或登录恢复后再次执行脚本；
- 没有修改：不提交、不推送，返回成功；
- 发布包检查失败：不提交、不推送，保留本地修改现场；
- 不提交密钥文件，现有 `.gitignore` 继续生效。

## 验证标准

- 脚本从任意当前目录执行都能定位小程序仓库；
- 脚本对无修改仓库不创建空提交；
- 新提交后 `HEAD` 与 `origin/main` 一致；
- 当前未提交的小程序修改能被一次同步完整推送；
- 发布包检查通过，产物非空且 ZIP 完整。
