# 本地人脸运行日志面板设计

## 目标

让用户在微信开发者工具模拟器和真机中，直接查看 `local-face` 的运行过程，并能复制完整诊断日志反馈问题。

## 现状

- `utils/local-face.js` 已将日志写入 `wx.setStorageSync("circle-face-runtime:debug-log")`。
- 日志最多保留 120 条，错误、WASM 探针和关键阶段会立即落盘。
- 首页目前只在运行失败时显示“复制诊断日志”，没有可展开的日志查看区域。

## 方案

### 页面交互

- 在本地人脸状态卡片中增加“查看运行日志（数量）”入口。
- 入口默认折叠，运行成功或失败后都可查看。
- 展开后显示最近日志，包含时间、级别、消息和详情。
- 提供“复制全部日志”和“清空日志”两个操作。
- 日志为空时显示明确的空状态，不显示无效按钮。

### 数据流

1. `localFace.subscribeStatus` 触发时，页面从 `localFace.getDebugLogs()` 读取当前日志。
2. 页面将日志转换成适合 WXML 展示的短文本，避免直接在模板中渲染复杂对象。
3. 复制操作继续使用现有完整 JSON 结构，包含版本、状态、WASM 探针摘要和全部日志。
4. 清空操作调用 `localFace.clearDebugLogs()`，同步清理内存和本地缓存。

### 兼容与安全

- 不改变 WASM 选择、MediaPipe 初始化或识别流程。
- 日志详情只做字符串化和截断展示，复制仍保留完整的现有限制范围。
- 日志面板本身不依赖云函数和网络。
- 真机不支持复杂模板能力时，仍能使用复制按钮获取完整日志。
