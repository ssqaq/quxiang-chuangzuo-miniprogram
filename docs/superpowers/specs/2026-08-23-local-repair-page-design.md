# 完整局部修正页设计

## 目标

为已生成的云端制作记录提供独立“局部修正”页面。用户可以在当前结果图上重新圈选区域、选择要修正的问题、补充参考素材并生成新版本。原记录不得被覆盖，修正版必须作为新记录追加保存。

## 页面入口

- 制作页生成结果卡增加“局部修正”按钮。
- 制作记录页的有效云端记录增加“局部修正”按钮。
- 本地临时记录、缺少记录编号的结果和父记录墓碑不能进入修正流程。
- 页面路由为 `pages/repair/repair?recordId=<记录编号>`。

## 页面结构

### 当前结果图

- 显示父记录当前图片。
- 使用独立 Canvas 绘制红圈，图片本身不被修改。
- 旧红圈只作为预填参考，用户必须重新拖动确认。
- 用户可重新选择主图；云端模式下通过受控素材上传流程登记。

### 素材状态

- 展示主图、mask、人脸参考、穿搭参考的准备状态。
- 新记录中已登记的参考素材可复用。
- 旧记录存在参考文件但没有登记版本时，必须重新补选，禁止直接复用。
- 人脸参考最多6张，穿搭参考最多12张。

### 问题选择

- 分类为人脸、背景、衣服、画质。
- “红圈外内容被改动”为默认且强制保留的问题项。
- 没有穿搭参考时隐藏依赖穿搭素材的问题项。
- 选项变化后立即重新生成修正指令。

### 修正指令与生成

- 根据项目名、问题项、参考素材和红圈位置生成只读修正指令。
- 支持复制修正指令。
- 提交前必须满足：
  - 云端已连接；
  - 父记录有效且不是本地记录；
  - 当前结果图具有云文件 ID；
  - 红圈已经重新确认；
  - 旧参考素材已重新登记；
  - 连续修正次数未超过10次。
- 生成按钮明确提示会消耗一次生图额度。

## 数据流

1. 页面按 `recordId` 从本地缓存和云端记录中查找父记录。
2. 加载图片临时地址、修正链信息、参考素材和旧红圈。
3. 用户重新圈选并确认问题项。
4. 客户端导出 mask，通过 `uploadAsset` 上传并登记。
5. 客户端调用 `repairImage`，携带：
   - `sourceFileID`
   - `maskFileID`
   - `parentRecordId`
   - `repairIssues`
   - `maskGeometry`
   - 已登记的人脸和穿搭参考
   - 新生成的 `requestId`
6. 云函数校验父记录归属、修正次数和素材票据。
7. 云函数复用图片生成的额度预留、幂等抢占、供应商调用和失败退款机制。
8. 成功后新增修正版记录，并写入父记录、根记录、修正序号和修正上下文。
9. 客户端把新记录追加到本地缓存并返回记录页。

## 安全与一致性

- 父记录必须属于当前微信 OPENID。
- 修正请求不得通过普通 `generate` 路由提交。
- 修正请求沿用 `generation_operations` 状态机。
- 同一 `requestId` 只允许一个供应商执行者。
- 供应商请求使用 `Idempotency-Key`。
- 退款后的原 `requestId` 永久禁止重试。
- 原记录不得被覆盖或删除。
- 父记录删除时，已有修正版保留并显示墓碑说明。
- 修正链最多10次，服务端为最终限制来源。

## 错误处理

- 记录不存在：提示记录加载失败，不进入生成。
- 图片地址失效：尝试使用云文件 ID 获取临时地址。
- 旧参考素材未登记：要求重新补选。
- mask 导出或上传失败：停止提交，不扣除新的生成额度。
- 供应商明确失败：状态记为失败并按原账单来源退款。
- 请求处理中：禁止重复点击，服务端返回处理中状态。
- 页面卸载后不再执行延迟跳转。

## 测试

- 页面脚本、JSON、WXML 和 WXSS 静态检查。
- 修正指令问题项规范化测试。
- 入口路由与记录编号传递测试。
- 本地记录和墓碑记录禁止修正测试。
- 红圈未重新确认时禁止提交测试。
- 旧参考素材未登记时禁止提交测试。
- 同一修正 `requestId` 并发只允许一次供应商调用。
- 修正失败只退款一次。
- 连续第10次允许、第11次拒绝。
- 父记录删除后子修正版仍可展示。

## 不包含

- 原图与修正版滑动对比。
- 任意版本回滚。
- 分支式版本树编辑器。
- 自动识别需要修正的问题。
- 批量修正多张图片。
