# 视频服务商修复与备用服务商设计

日期：2026-08-28

## 目标

修复管理员页面的视频服务商配置体验，并增加一个可配置的视频备用服务商。普通生图、图片分析、人脸识别和现有视频接口保持兼容。

## 方案

复用现有的 `providerProfiles.video` 服务商档案：

- 保留当前视频主服务商选择。
- 新增“备用视频服务商”选择。
- 主、备用服务商各自读取自己的模型、地址、创建路径、查询路径、清晰度、超时和密钥。
- 管理员保存配置后，云函数只保存配置，不把密钥写入前端日志、发布包或普通运行日志。

## 运行流程

1. 用户点击一次视频生成，后端使用同一个 `requestId` 预扣一次额度。
2. 先调用主视频服务商创建任务。
3. 如果主服务商在“创建任务”阶段返回明确的网络错误、超时、403、429 或 5xx，且备用服务商已配置，则只尝试一次备用服务商。
4. 任一服务商成功创建任务后，记录实际使用的服务商；后续查询固定使用这个服务商，不再切换。
5. 两个服务商都创建失败时，按现有逻辑失败并退款。
6. 重复使用同一个 `requestId` 时返回已有任务结果，不重复扣费、不重复创建上游任务。

## 管理员页面

- 视频配置区域显示“主视频服务商”和“备用视频服务商”两个下拉框。
- 备用项提供“未启用”，不能误选成主服务商。
- 切换服务商后自动载入对应档案；参数可以单独修改并保存。
- 测试连接只测试当前正在编辑的服务商，不扣额度。
- 页面显示当前配置是否完整和最近一次测试结果，但不输出完整密钥到日志或发布包。

## 错误处理

- 只有创建阶段的可切换错误才触发备用服务商。
- 上游已经返回任务编号后，不再切换，避免同一请求生成两条视频。
- 主服务商失败、备用未配置时，直接返回清晰错误原因并退款。
- 备用服务商也失败时，返回主服务商和备用服务商的简要失败状态，隐藏密钥内容。
- 查询阶段只使用任务记录中的实际服务商，避免管理员后来改配置导致旧任务查错接口。

## 数据兼容

- 兼容没有 `videoBackup` 字段的旧配置，按“未启用”处理。
- 兼容旧视频任务：没有实际服务商记录时继续使用当前主视频配置查询。
- 不改普通生图的配置键和调用链路。

## 测试验收

1. 管理员页面能选择和保存主、备用视频服务商。
2. 备用服务商档案参数能正确载入和保存。
3. 主服务商成功时不调用备用服务商。
4. 主服务商在可切换错误时只调用一次备用服务商。
5. 主服务商返回任务编号后，即使后续查询失败也不切换备用服务商。
6. 两个服务商都失败时只退款一次。
7. 相同 `requestId` 不重复扣费、不重复创建任务。
8. 线上配置或日志中不出现密钥明文。
9. 普通生图相关测试保持通过。
