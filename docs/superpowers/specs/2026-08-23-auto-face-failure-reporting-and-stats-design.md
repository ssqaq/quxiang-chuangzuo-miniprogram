# 自动贴脸失败日志上传与管理员统计设计

## 目标

把自动贴脸失败从“只在当前手机上提示”变成“用户能继续操作、后台能查原因、管理员能看趋势”：

1. 自动贴脸失败后，静默上传一条脱敏失败记录；
2. 上传失败不能阻塞手动圈选，也不能再次弹出干扰用户；
3. 管理员页显示最近 30 天的失败数量、失败类型和最近记录；
4. 不上传主图、云文件 ID、API Key、Prompt 或完整设备诊断报告。

## 方案选择

采用独立的自动贴脸失败日志集合，不复用部署检查日志。

- 部署检查日志回答“线上部署和配置是否正常”；
- 自动贴脸失败日志回答“用户这次为什么没识别成功”；
- 两类记录分开，管理员排查时不会混在一起。

## 数据结构

新增 CloudBase 集合：`auto_face_failure_logs`。

每条记录只保留以下字段：

| 字段 | 用途 |
|---|---|
| `requestId` | 对照前端提示和云函数日志 |
| `failureType` | 统一失败分类，例如 `timeout`、`upstream`、`empty-face-detection` |
| `errorCode` | 服务端原始错误码 |
| `message` | 清洗后的短错误摘要，最多 240 个字符 |
| `status` | HTTP 状态码，没有则为 0 |
| `retryable` | 是否可以重试 |
| `stage` | 失败发生阶段 |
| `durationMs` | 本次自动贴脸耗时 |
| `appVersion` | 发生失败时的小程序版本 |
| `createdAt` | 服务端写入时间 |

服务端重新截断和清洗字段，禁止客户端直接写入任意对象。记录不包含图片路径、`fileID`、Prompt、Key、Token、堆栈和完整设备信息。

## 数据流

### 用户端

1. `autoFaceCircle()` 捕获失败；
2. 页面照常调用现有 `enterManualFaceCircle()`；
3. 页面根据已有错误信息生成 `failureType` 和中文原因；
4. 通过 `cloud.reportAutoFaceFailure()` 异步上报；
5. 上报成功或失败都不改变用户当前页面和手动画圈流程。

上报接口使用不重试或最多一次的策略，避免网络异常时形成额外请求。上报失败只写入本地诊断日志，不弹窗。

### 云函数

新增两个 action：

- `reportAutoFaceFailure`：普通用户可调用，写入清洗后的失败记录；
- `getAutoFaceFailureStats`：仅管理员可调用，读取和汇总最近 30 天记录。

管理员统计接口只查询服务端时间范围内的记录，最多读取 500 条，避免一次读取过多数据。返回结果包括：

- `total30d`：最近 30 天总失败数；
- `today`：今天失败数；
- `last7d`：最近 7 天失败数；
- `byType`：按失败类型汇总；
- `recent`：最近 20 条简短记录。

统计接口不返回用户身份字段。

## 管理员页面

在现有管理员页的部署日志区域前新增“自动贴脸失败统计”卡片：

- 顶部显示“今天 / 最近 7 天 / 最近 30 天”三个数字；
- 中部显示失败类型和次数；
- 底部显示最近失败时间、失败类型、错误码、状态码和请求编号；
- 提供“刷新统计”按钮；
- 没有记录时显示明确的空状态；
- 读取失败只显示页面提示，不影响模型配置和部署检查功能。

## 错误处理与安全

- 自动贴脸失败上报必须是 fire-and-forget；
- 上报接口异常不能覆盖真实失败原因，也不能阻塞手动圈选；
- 管理员接口继续复用现有 `ADMIN_OPENIDS` 白名单；
- 服务端统一限制字符串长度，过滤 Key、Token、路径和对象型扩展字段；
- 统计接口只返回聚合数据和必要的短记录；
- 云函数数据库写入失败记录告警日志，但不向用户暴露数据库细节。

## 测试与验收

1. 云函数能正确清洗失败字段，丢弃图片、Key、Prompt 和堆栈；
2. 非管理员调用统计接口返回 `ADMIN_FORBIDDEN`；
3. 管理员能拿到 30 天汇总、分类计数和最近记录；
4. 自动贴脸失败后仍进入手动圈选，上报失败也不影响页面；
5. 管理员页面能显示统计卡片、空状态和刷新失败提示；
6. 现有管理员配置、部署日志、自动贴脸回退和全量静态校验继续通过；
7. 完成后升 patch 版本、正式打包并刷新预览码。
