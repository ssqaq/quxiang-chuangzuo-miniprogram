# 发布链路四项安全保护设计

## 目标

解决并行任务同时修改主工作区时，出现错配发布包、串提交和版本说明落后的问题。

本次落地四项保护：

1. 发布过程加全局锁。
2. 打包前后校验 Git SHA。
3. 发布包记录最终提交 SHA。
4. 并行任务只能在 worktree 或独立分支开发，禁止直接在 `main` 提交。

## 方案

### 1. 发布锁

`scripts/sync-to-github.ps1` 在拉取远端前获取项目目录旁的独占文件锁，锁覆盖拉取、暂存、预检查、提交、正式打包和推送全过程。

锁使用独占 `FileStream`，进程异常退出时由操作系统释放，不依赖手工删除 stale lock 文件。

### 2. SHA 与来源隔离

同步脚本不再使用 `git add -A`。调用方必须通过 `-IncludePath` 显式指定本次发布文件。

暂存完成后使用 `git write-tree` 得到本次暂存内容的 Git tree SHA，并让发布脚本从这个 tree 打包。这样工作区里其他并行任务的未暂存文件不会进入发布包。

预检查包完成后再次确认 `HEAD` 没有变化；提交后使用最终 commit SHA 重新生成正式发布包，并在推送前再次确认 SHA 没有变化。

### 3. 发布清单

`RELEASE-MANIFEST.txt` 增加：

- 最终提交 SHA。
- Git tree SHA。
- 源码内容 SHA256。
- 打包类型。

正式发布包中的提交 SHA 必须等于本次推送的 commit SHA。

### 4. main 分支保护

新增 `.githooks/pre-commit`：

- 在 `main` 上直接执行 `git commit` 时拒绝提交。
- 只有同步脚本设置的临时环境变量可以放行。
- 独立分支和 worktree 不受影响。

同步脚本同时要求运行目录是主仓库根目录、当前分支是 `main`，避免在 worktree 里误发布主分支。

## 错误处理

- 锁被占用：立即失败，提示当前锁路径。
- 未显式指定发布文件：立即失败，避免把并行修改一起暂存。
- 暂存 tree、预检查前后或提交后 SHA 不一致：立即停止，不推送。
- 预检查包失败：不提交、不推送。
- 正式包失败：保留本地提交但不推送，等待修复后重试。
- 推送失败：保留本地提交和发布包，方便恢复。

## 验证

- 发布脚本静态检查：确认无 `git add -A`，存在锁、SHA 校验和 main/worktree 保护。
- 发布包 smoke：从 `HEAD` 打包，检查清单中的 commit SHA、tree SHA、源码指纹和 ZIP 完整性。
- pre-commit smoke：确认 hook 在 `main` 拒绝直接提交、在独立分支允许提交。
- 正式 `scripts/validate.js`。
- 正式发布包生成并检查文件大小、清单和 SHA。
