# 任意方向手动红圈设计

## 目标

让主图上的手动红圈支持从任意位置开始，并向任意方向拖动：

- 左上 → 右下
- 右下 → 左上
- 左下 → 右上
- 右上 → 左下

拖动起点和终点表示椭圆外接框的两个对角点，拖动顺序不影响最终红圈位置和大小。

## 已确认问题

当前页面的红圈计算虽然使用了 `Math.abs()`，但计算函数直接嵌在页面对象中，触摸流程仍存在两个不稳定点：

1. `touchmove` 和 `touchend` 直接取数组第一个触摸点；
2. `touchend` 优先使用 `changedTouches[0]`，没有确认它就是开始绘制的那根手指。

在单指绘制和双指缩放切换、触摸点顺序变化或真机事件字段不完整时，终点可能不是实际绘制手指的位置，导致反向拖动看起来像只能从左上拖到右下。

## 方案

### 1. 抽出纯计算工具

新增 `utils/circle-gesture.js`：

- 接收起点、终点、原图宽高；
- 用 `min/max` 计算左、上、右、下边界；
- 对边界和最小尺寸做统一裁剪；
- 返回现有业务格式 `{ x, y, width, height }`；
- 不依赖微信页面对象，便于 Node 测试。

### 2. 锁定绘制触摸点

在首页绘制流程中：

- `touchstart` 保存 `identifier`；
- `touchmove` 优先从 `event.touches` 找到相同 `identifier`；
- `touchend` 优先从 `changedTouches` 找到相同 `identifier`；
- 每次移动保存最后一个有效点，避免结束事件没有有效坐标时丢失终点；
- 进入双指缩放时清理单指绘制状态。

### 3. 不改变现有交互

- 双指缩放、平移逻辑保持不变；
- 自动贴脸生成的 `maskCircle` 数据格式保持不变；
- mask 导出仍使用中心点和宽高，不需要改后端接口；
- 只更新手动圈选的计算与触摸取点逻辑，并补充用户提示文案。

## 错误处理与边界

- 起点、终点缺失时使用最后一个有效点；
- 坐标超出画布时裁剪到画布边缘；
- 起点和终点几乎重合时保留现有最小红圈尺寸；
- 图片宽高或画布宽高无效时返回安全的最小结果，不抛出页面异常。

## 验证

新增纯函数测试覆盖：

1. 四种对角方向产生相同的结果；
2. 触摸点超出边界时仍不会生成越界框；
3. 起点和终点重合时仍满足最小尺寸；
4. 触摸 `identifier` 变化时仍能找到正确的绘制点。

然后运行：

- `node scripts/canvas-gesture-smoke.js`
- `node scripts/circle-gesture-smoke.js`
- `node scripts/validate.js`
- `node scripts/compat-smoke.js`
- `node scripts/image-smoke.js`
