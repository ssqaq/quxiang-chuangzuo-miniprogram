# 管理员模型选择搜索与连接失败提示设计

## 目标

在管理员页现有“获取模型”和“测试连接”功能上做两项小改动：

1. 模型列表弹窗增加搜索框，按模型名称包含关键词实时筛选，大小写不区分。
2. 连接测试失败时显示后端返回的具体原因，而不是只显示“连接未通过”。

## 方案

### 模型搜索

- 服务端仍只负责读取一次模型列表。
- 弹窗打开后保存完整模型列表，同时维护一个搜索关键词和一个筛选后的列表。
- 输入关键词时只在本地筛选，不重复请求接口。
- 关键词为空时显示完整列表。
- 没有匹配项时显示“没有找到相关模型”。
- 关闭弹窗时清空关键词和筛选状态，避免下次打开残留上次搜索内容。

### 连接失败提示

- 优先使用 `probeModels` 返回的 `message`。
- 如果服务端请求直接抛错，提取错误响应中的 `message`、`error` 或状态信息。
- 对常见失败情况显示清楚的中文原因：未填写配置、API Key 无效、接口地址打不开、当前模型不存在、接口返回格式不兼容、网络异常和上游服务异常。
- 不在提示中显示 API Key 原文。

## 数据流

1. 管理员点击“获取模型”，读取模型列表并打开弹窗。
2. 管理员输入关键词，页面实时更新筛选结果。
3. 管理员点击模型，继续沿用现有逻辑填入模型框。
4. 管理员点击“测试连接”，后端探测接口并返回状态和原因。
5. 页面将具体原因显示在提示框和页面状态信息中。

## 验证

- 页面 JavaScript 语法检查。
- 云函数 JavaScript 语法检查。
- 模型列表搜索逻辑测试：空关键词、大小写混合关键词、无匹配结果。
- 连接失败提示测试：后端明确失败消息、网络异常、无消息异常。
- 页面布局与已有管理员页专项测试。
- `git diff --check`、正式打包和 GitHub 同步。
