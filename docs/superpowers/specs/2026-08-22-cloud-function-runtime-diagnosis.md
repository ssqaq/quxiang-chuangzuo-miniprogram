# 云函数运行包诊断与修复方案

## 背景

体验版点击“红圈自动贴脸”时，云函数 `api` 报：

```text
Cannot find module './lib/multipart'
```

本地源码和通过微信开发者工具 CLI 下载回来的远端函数包都包含
`lib/multipart.js`，且关键文件内容一致。因此本轮先定位体验版实际命中的
环境、版本和运行包，不改前端或自动贴脸业务逻辑。

## 方案

1. 保持现有 `--paths` 指向
   `cloudfunctions/api` 的部署方式，不改成项目根目录扫描。
2. 在云函数入口最前面增加唯一构建标记日志，且放在所有 `require` 之前，
   用于判断体验版是否真的命中新部署的入口文件。
3. 将版本从 `0.6.4` 升到 `0.6.5`，同步小程序配置、云函数
   `package.json` 和 lock 文件。
4. 完成静态检查、兼容检查、正式打包和云函数重新部署。
5. 通过云开发控制台日志观察
   `API_BUILD_TAG_20260822_01`：
   - 出现：体验版命中新入口，继续定位运行包结构或运行时；
   - 不出现：体验版仍未命中新部署的环境或版本。
6. 定位完成后删除临时日志，再做一次补丁版本发布。

## 风险控制

- 不修改前端按钮、自动贴脸算法和 `multipart.js` 业务代码。
- 不删除云函数、环境、版本或流量配置。
- 重新部署前保留本地源码和远端下载备份。
- 云端测试使用不产生真实业务副作用的参数。
