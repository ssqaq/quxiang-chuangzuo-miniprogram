# 备用生图模型四项配置设计

## 目标

在管理员页“生图模型”配置中，让备用模型和主模型一样直接显示并可配置以下四项：

1. 模式；
2. 尺寸比例；
3. 清晰度（价格/张）；
4. 超时毫秒。

备用模型的四项配置独立保存、独立读取。主模型失败并切换到备用模型后，后台必须使用备用模型自己的参数，不能继续沿用主模型的尺寸、清晰度或超时。

## 页面设计

备用模型区域保持现有两列网格，不增加新的折叠层级。API Key 下方按主模型的顺序补齐：

```text
模式                 清晰度（价格/张）
尺寸比例             超时毫秒
备用调用次数
```

- “模式”显示并保存 `form.imageBackup.mode`。第一版仍固定为 `edits`，与当前图片编辑流程一致。
- “清晰度（价格/张）”使用独立选择器，选项为 `1K`、`2K`、`4K`，价格按备用服务商对应的成本表显示。
- “尺寸比例”使用独立选择器，不复用主模型选择器的索引。
- “超时毫秒”继续使用现有 `form.imageBackup.timeoutMs` 输入框，只把标题统一为“超时毫秒”。
- “备用调用次数”继续固定为 1，不增加底层重试。

## 数据与保存

管理员页面增加备用模型独立选择器状态：

- `imageBackupQualityOptions`
- `imageBackupQualityIndex`
- `imageBackupSizeOptions`
- `imageBackupSizeIndex`

新增两个备用模型事件：

- 选择清晰度时只更新 `form.imageBackup.resolution`；
- 选择尺寸比例时只更新 `form.imageBackup.size`。

保存配置时：

- `imageBackup.mode` 不再写死为 `edits`，从表单读取并规范化；
- `imageBackup.size` 不再自动退回主模型值，优先保存备用模型自己的值；
- `imageBackup.resolution` 不再自动退回主模型清晰度，优先保存备用模型自己的值；
- 旧配置没有这两项时，读取阶段仍允许继承主模型当前值，避免线上旧数据突然变空。

## 后台调用

云函数现有 `resolveImageBackupConfig` 已经能独立解析：

- `mode`
- `size`
- `resolution`
- `timeoutMs`

主备编排也会把完整备用配置交给备用调用。因此本次重点是确保管理员页真实保存这些值，并补测试证明备用调用没有偷用主模型参数。

## 兼容与边界

- 不修改主模型重试次数和主备切换顺序。
- 不修改普通“开始新创作”和腾讯版的业务流程。
- 不改 API Key 保存方式，不把密钥写进源码、日志或发布包。
- 不新增备用模型底层重复重试。
- 旧版云端配置缺少备用尺寸或清晰度时，页面第一次加载使用主模型值作为兼容默认；管理员保存后形成独立配置。

## 验收标准

1. 备用模型区域可看到模式、尺寸比例、清晰度（价格/张）、超时毫秒。
2. 修改备用清晰度不会改变主模型清晰度。
3. 修改备用尺寸比例不会改变主模型尺寸比例。
4. 保存并刷新后，备用四项配置保持不变。
5. 主模型失败切换备用模型时，备用请求使用备用 `mode`、`size`、`resolution`、`timeoutMs`。
6. 旧配置没有备用尺寸或清晰度时仍能正常打开和保存。
7. 主模型、腾讯换脸、视频、制作记录和积分流程不受影响。
8. 专项测试、完整检查、版本升级、正式打包、云函数部署和线上核验全部通过。
