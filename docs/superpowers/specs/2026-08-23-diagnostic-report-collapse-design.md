# 故障排查报告卡片收起/展开设计

## 目标

让工作台上的“故障排查报告”卡片默认保持紧凑，只在用户需要时展开查看日志，减少页面长度和视觉干扰。

## 交互方案

- 默认状态：收起。
- 收起状态：只显示“故障排查报告”标题和右侧统计数字。
- 展开入口：点击卡片顶部标题区域。
- 展开状态：显示说明文字、“收起日志 / 复制报告 / 清空”三个按钮，以及日志明细。
- 收起入口：再次点击卡片顶部标题区域。
- 原有日志操作不变：
  - “复制报告”继续复制完整排查报告。
  - “清空”继续清空日志，并保持卡片收起。
- 页面重新进入工作台时恢复默认收起，不保存展开状态。

## 页面结构

- 复用现有 `diagnosticExpanded` 状态，不新增存储字段。
- 将现有卡片头部作为唯一的收起/展开触发区域。
- 说明、操作按钮和日志列表统一放进 `wx:if="{{diagnosticExpanded}}"` 区域。
- 头部增加明确的“展开 / 收起”提示和箭头，避免用户看不出卡片可以点击。
- 操作按钮区域使用 `catchtap`，避免点击按钮时触发卡片头部的展开/收起。

## 样式要求

- 收起时卡片高度明显降低，只保留标题行。
- 展开时沿用当前浅蓝色卡片、按钮和日志列表样式，不改方案 B 的整体视觉。
- 头部保持可点击反馈，箭头根据状态旋转。
- 手机窄屏下标题、统计数字和展开提示不重叠。

## 验证

- 静态检查通过。
- 工作台交互测试覆盖：
  - 初始 `diagnosticExpanded` 为 `false`。
  - 点击头部后变为 `true`。
  - 再次点击头部后恢复 `false`。
  - 复制报告和清空日志仍可用。
- 微信开发者工具中确认：
  - 首次进入默认收起。
  - 展开后能看到说明、按钮和日志。
  - 点击按钮不会误触发卡片收起/展开。
